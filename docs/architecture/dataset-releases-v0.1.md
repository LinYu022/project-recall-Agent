# P1-06：DatasetRelease 与跨存储一致性

日期：2026-10-27。正式查询入口为 `app.release_api:create_release_app`；P1-03/P1-05 的快照检视和索引 API 保留为开发诊断入口，不代表已发布调查结果。

## 三个身份与两个阶段

- dataset_build_id：固定语料、分块和构建配方。
- index_artifact_sha256：进一步固定 BM25、向量、模型与检索配置。
- release_id：固定完整发布清单，包括原始文件、映射、解析/分块、规则、BM25/向量/配置、Qdrant 逻辑组件、模型文件及 Python/锁文件环境。

`build` 生成候选和不可覆盖清单，但不改变数据库默认值；只有完整校验与数据库对账通过后，`publish` 才能提交默认指针。文件、Qdrant、PostgreSQL 没有共同事务，因此不声称一次原子写入所有存储。外部组件先准备好，PostgreSQL 是可见性边界；失败候选或预先导入的版本行不会自动成为默认发布。

## 独立发布包

BundleStore 在 `.local/releases/bundles/` 保存每个构建的独立副本。为兼容 Windows 深层目录，物理目录使用完整 bundle_key/index 哈希的前 24 位；bundle.json 和 Qdrant component.json 仍保存完整身份并校验，发生碰撞时拒绝复用，不以短名代替身份。

清单列出每份文件的相对路径、大小和 SHA-256，并严格检查角色集合完整、无重名、无路径越界。相同构建重复保存复用相同内容；已有文件不同则拒绝，不就地修补。

包含：原始 objects/snapshots、完整确定性映射、每份解析/分块工件、五类规则、索引及独立 BM25/向量/配置组件、两种模型身份与全部权重/tokenizer/配置/卡片、uv.lock 和 pyproject.toml。正式包不能打开标记为 test_only 的合成模型包。

Qdrant 的 SQLite 文件可能因运行时锁等改变，因此不把物理数据库字节当作永久不变哈希。清单绑定 component.json，校验器再逐点比较数量、完整载荷和向量与固定索引；缺数据库或清单不会自动重建。当前是持久化本地精确模式，未测试远端 Qdrant 服务/HNSW。

## 校验器

1. 校验发布 Schema、release_id、完整路径/文件清单及字节哈希。
2. 校验索引内部文档、BM25、归一化向量，以及独立组件共同的 dataset_build_id。
3. 使用包内规则和固定原始字节，在单独 scratch 目录重建语料，与封存语料完全比较；引用和分块工件从原文重放。不会通过验证修补发布包缺失的工件。
4. 比较映射结果、模型/index 身份、每个模型资产与其固定身份的哈希，以及环境文件与解释器。
5. 检查必需角色集合完整，逐点核对 Qdrant，随后才能登记发布清单。

已发布任务的每次查询也执行完整校验，并核对数据库映射、来源行血缘、实体投影及展开行、release_records 成员和任务绑定。这样可以检测数据库与索引混用，代价是每次查询都较重。`published_elapsed_ms` 包含发布验证、模型加载及检索；原 `total_ms` 仍是检索阶段时间，不能把 P1-05 的纯检索耗时当作本入口总耗时。

## PostgreSQL 0004

| 表 | 作用 |
| --- | --- |
| dataset_releases | 不可变清单/构建/包身份、available/retiring/collected 状态、保留期限 |
| release_records | 发布与具体映射版本及完整记录哈希的成员关系 |
| release_defaults | 单一 default 指针 |
| release_tasks | 任务固定 release_id、来源/范围快照、spec 哈希及 active/finished/cancelled 引用状态 |
| release_report_refs | 报告或调查工件引用；无 keep_until 表示持续保留 |
| release_events | 发布、回滚、绑定、结束和回收审计 |

发布先幂等准备来源/实体数据，再在事务内重新验证文件和数据库。使用按 schema 区分的 advisory lock；写操作独占，查询共享。默认更新使用 expected_default 比较并交换，两个并发发布不能互相悄悄覆盖。发布登记、成员、默认指针和发布事件在同一事务中；指针更新后故障会全部回滚。已存在发布的保留期限只允许延长。

这是当前本地控制锁实现，不是分布式存储事务。直接绕开应用协议修改数据库或文件是不受支持的管理操作；后续读取仍会检查已声明的完整性条件。

## 任务绑定与查询

新任务仅在 `/tasks/bind` 时选择默认发布，也可指定一个完整可用的旧发布。绑定后 release_id、允许来源和业务范围不可改写。同一任务以相同输入重试仍返回旧绑定，不重新读取最新默认值。P1-08 再集成完整授权与任务状态机；这里的 active/finished/cancelled 仅用于引用保留，不等于调查质量终态。

正式查询只收 task_id、query、method、top_k，以及可选 expected_release_id。客户端不能在单次查询覆盖路径、来源、范围、数据构建或发布；expected_release_id 与任务不同时拒绝。

- `/published/search`：继承固定来源、范围、时间和索引；返回 release_id、manifest_sha256 与轨迹。
- `/published/expand`：从该任务的原始字节展开焦点/父块/必要上下文，不能拿新索引的文档 ID 混入旧任务。
- `/published/complaints/count`：复用结构化全集去重计数，固定任务的来源/时间与车辆条件；生产日期点条件转为相应区间，未知仍 partial；不能静默忽略配置/召回条件，不支持时返回 unsupported/null。
- `/published/entity-links`：两端必须位于固定发布和任务允许来源内。结果附两端 scope 通道及“关系核查，非适用证据”用途；显式引用不晋升为因果或个车适用证明。

发布、回滚、引用结束、引用登记和回收仅放在本地 CLI，不提供匿名远程管理路由。当前为单用户开发服务，完整 grant/revision 授权在 P1-08。

## 回滚、保留与回收

回滚切回先前完整可用的 release_id，使用相同校验与 expected_default，不覆盖文件或已有任务。新任务使用回滚后的默认值，已绑定任务仍固定原版本。

回收前检查：是否默认、是否有 active 任务、是否有未过期/永久报告引用、是否达到至少 manifest.retention_days 的保留期限。默认只返回计划。显式 --execute 且全部条件满足后，先提交 retiring 阻止新绑定/引用，再删除该发布的独立目录，最后标记 collected。中断后保留 retiring 状态，可重试完成；不回退到别的发布。

删除前验证精确目标解析后的父目录就是拥有的 bundles 目录，拒绝越界或逃逸 symlink。不会删除全局原始快照、全局索引/模型，或共享 PostgreSQL 记录；清单、审计、任务和引用元数据保留。共享数据库数据的物理压缩/归档不属于这次独立包回收，不假称已经回收所有共享行。

## 已验证边界

268 项无数据库测试、51 项真实 PostgreSQL 测试通过；包含缺组件、工件篡改、跨构建、数据/投影/血缘/任务哈希混用、并发 CAS、回滚、引用保留及中断后回收。合成保留测试使用明确推进的测试时钟；没有等待现实保留期或删除受保护的真实包。

两个真实资料包分别有 106/225 条记录、117/593 个块、242/498 份校验文件。20 项真实发布流程检查包含 9 类本机 HTTP；旧任务跨发布保持原块，新任务使用新增资料，回滚、原文引用、103/86/5 计数、未知生产日期和官方引用关系均已核对。临时 HTTP、PostgreSQL 和隔离 schema 已清理；没有永久部署默认发布，也没有新增外部来源或生成式模型请求。
