# 角色分离的事后审查 v0.2

本轮补齐P1-16审查工程，复用已保存的真实输出，不运行调查或调用模型。`reviewing/`与冻结生成器`evaluation/`分开；原协议、报告、标签、v0.1评分和审查索引保留。该口径在看过测试输出和人工反馈后形成，因此明确属于事后分析，不能替代原计划要求的测试前质量目标。

## 数据与依赖

`corpus.load_cells()`先用原冻结加载器核验生成实现，再读取270格索引、269份实际观察及209份请求输入。观察、报告、参考标签和输入按哈希核对；未运行的一格没有观察，也不生成虚构盲审包。

`prepare()`封存策略、分析代码、全格绑定与可信人工原记录，生成独立assessment_id，并留存分析代码快照。当前身份为`137288e5a173ef36db82beb91b0bdf39a0237f5d20e1e5a64e29bf62b94ea752`；[公开manifest](../../evals/role-aware-review-v0.2/assessment-manifest.json)包含全部绑定。此前三个开发版本保留，不能拿旧身份运行新代码。

`import_review()`核验报告/观察/标签/策略身份与原回复登记，再保存不可变审查工件。完全相同的重复导入幂等；同格出现多份人工审查时保留争议、指标留空，需实际裁决并创建新的登记版本。`reviewer_kind=human`字段本身不能证明来自人类；登记依据是维护者核对本任务的真实回复。这不是第三方身份认证系统。

## 三种角色与五层判断

| 层次 | 核查内容 | 不能据此推得 |
| --- | --- | --- |
| 引用角色 | direct、required_context、both、counterevidence或unresolved | 上下文必然直接支持结论 |
| 引用的指定方面 | 人类明确评价的那部分内容是否受引文支持 | 整个复合句全部受支持 |
| 整条结论 | 主体、范围、条件和各部分是否准确 | 答案没有遗漏题目义务 |
| 原子断言/必需义务 | 精确文本区间、引用映射、缺失和反证 | 高引用分自然意味着整题成功 |
| 整题 | 实际人工完整阅读、处置和任务完成判断 | 一份样例可代表方法总体质量 |

`contracts.py`把这些判断分成不同字段。原子断言必须精确对应原句的非重叠区间；声称穷尽时必须覆盖全部有意义文本。义务满足需指明答案结论与其实际引用，新增等价证据需明确理由。required_context递归检查，环或缺失明确拒绝，不能随意给无关引用贴上context标签将其移出直接支持分母。

`scoring.assess()`分别计算缺测。直接引用按审查者指定方面计分；部分支持与不支持分开。当前不从方面评价推算整句引用支持率。程序完整性检查与真实人工语义判断配合；实现代理和合成样例只有provisional结果。

正向的严格任务成功要求完整、正向的结论/原子断言/义务/引用/关系审查，以及原证据与结论契约通过。负向实际整题判断可以保留，而不凭它补造各项分数。这种严格指标与人工的“核心要求完成”定性判断是不同口径：本次历史开发答案的正向原判单独完整保存，未被改成失败，也没有强行填充严格指标。

`analyze()`始终保留270分母，逐臂输出审查覆盖数；任何缺审/争议都不按零分处理，未覆盖全分母时总体质量指标为null。运行失败与正确澄清停止各自保留原状态，需要相应实际任务评价，不能只评价已有答案的子集。

## 原始证据与实际输入

盲审包同时保留原始证据和与已保存模型输入精确匹配的最小化内容。文本匹配要求来源和最小化文本相符；结构化查询另核对精确payload。找不到精确匹配只标记尚未解决，不能断言未输入。

在已审冻结测试中，原文电话号码被替换；E001查询摘要保留scope、counts、coverage等字段，但移除了`rows`，其中的`make_unknown/model_unknown`原因没有进入这份匹配的查询payload。缺陷条件、通知和应急文字则可见。因此端到端信息丢失与模型遗漏可见信息分别记录，人工原判不覆盖；如另有等价信息需另做输入核查。

历史开发包`DEVBLIND-cfeac5b7d689`的当时输入尚未核查。审查者已明确不把省略直接归因于模型。
