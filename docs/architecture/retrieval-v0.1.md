# P1-05 检索服务与可复现契约

## 数据与索引

BuildRequest 固定 snapshot_ids、时间语义和分块策略。构建复用 P1-02 时间选择、P1-03 的实体映射/版本化条件事实、P1-04 解析与分块。部分或不支持的时间选择阻止构建；没有使用 latest 回退。当前输入是 12 个固定来源选择、225 条来源记录；生成 593 个叶块，149 个去重证据组。

JSON 元数据来自已验证字段及确切版本的条件规则。新增 `retrieval-entity-rules/0.1` 扩展已观察到的官方品牌/车型标签，不改写旧映射。PDF 的车型、制造商和召回引用由三份精确引用支撑的审查配置提供；它不把调查文件当成召回车型记录，也不从自然语言猜生产日期或配置。

每个索引文档固定来源、解析工件、分块工件、chunk_id、原始范围、元数据、叶块原文及 search_text 哈希。所有方法使用相同 search_text：简短编号/车辆/部件/已审查配置、标题路径和叶块正文。哈希和原始文件路径不放进模型输入，避免无意义字符串占用上下文。

dataset_build_id 固定语料与构建配方；index_artifact_sha256 进一步固定 BM25、归一化向量、编码模型和检索配置。它们都不是正式 release_id；P1-06 负责跨组件发布清单和默认版本的原子切换。

## 向量存储与完整性

生产 CLI/API 使用 Qdrant 客户端的持久化本地模式，按索引哈希隔离目录；NumPy 精确余弦实现仅作参考和合成契约测试。当前语料规模使用精确检索，未宣称运行过远端 Qdrant 服务、HNSW 或生产负载实验。

Qdrant 的 component.json 绑定索引哈希、数据构建 ID、维度、点身份列表、距离和客户端版本。点 ID 由 document_id 确定性生成。加载时核对清单、点数、每个载荷和向量；缺组件、错载荷、删点、改向量均拒绝。查询先确定允许的点 ID，再以 HasIdCondition 过滤。不会因组件缺失切回 NumPy 或另一个索引。

构建可能留下未完成的独立目录；没有清单的已有集合拒绝当成成功组件。不得把本模块的文件/Qdrant 写入说成已具备跨存储事务或正式发布保证，这属于 P1-06。

## 范围通道与重复文本

SearchRequest 固定 dataset_build_id、query、allowed_source_ids、scope、method、top_k。服务器再限制可访问来源，请求不能扩大服务器选择。当前是本地单用户开发接口；完整 grant/revision 授权由 P1-08 实现。

| 通道 | 条件 | 输出含义 |
| --- | --- | --- |
| matched | 所有请求的已支持硬条件均匹配 | 范围匹配候选；尚非个车适用或结论支持证明 |
| pending | 没有已知冲突，但有必需元数据缺失 | 单独待核查，不提升成已匹配证据 |
| excluded | 已知品牌/车型/年份/编号/部件/生产日期/配置冲突 | 不进入任何排序或重排候选 |

车辆条件在同一个车辆位置上联合判断，不能把第一辆的品牌和第二辆的年款拼成匹配。型号年不代替生产日期，未提取配置不视为满足配置。相关性或重排分数不能改变通道。

官方召回 API 按车型年重复同一段说明。先过滤，再以“来源类型、召回编号或具体来源版本、字段、叶块文本哈希、父块文本哈希”定义 evidence_key。各通道只对相同证据组排序一次，组分数为成员最高分，展示代表是本通道允许成员中 document_id 最小者；保留 equivalent_document_ids 回查其余位置。RRF 对相同组的代表合并排名。不是按相似语义合并不同缺陷或不同投诉。

## 四条排序路径

- BM25：确定性词项、词频饱和、长度归一化。k1=1.2、b=0.75。`10V-039` 这一明确短编号格式映射为 `10V039000`；不把任意相似编号当精确匹配。
- dense：MiniLM 对 search_text 编码，attention mask 均值池化、L2 归一化，经 Qdrant 余弦排序。与文档一致的模型身份是查询前提。
- hybrid：各通道分别取 BM25/dense 前 30 个证据组，使用 `sum(1/(60+rank))` 融合，保留 30 个候选。
- hybrid_rerank：同一 hybrid 候选集最多 30 项，由交叉编码器对 query/passage 联合打分。输出原始 logit，按分数排序；不是概率、置信度或缺陷认定。

重排只能调整已召回候选，无法找回未入候选的资料。所有分数相同以 document_id 作为稳定顺序。BM25 对去重词项排序后累加，减少跨进程集合遍历导致的浮点顺序差异。

## 模型、截断与开销

| 角色 | 仓库 / 固定修订 | 配方 |
| --- | --- | --- |
| encoder | Xenova/all-MiniLM-L6-v2 / 751bff37182d3f1213fa05d7196b954e230abad9 | int8 ONNX、384 维、256 token、mask mean + L2 |
| reranker | Xenova/ms-marco-MiniLM-L-6-v2 / a09144355adeed5f58c8ed011d209bf8ee5a1fec | int8 ONNX、512 token、raw logit；query 最多 128 token |

使用 CPUExecutionProvider、单线程、批量 8。模型文件、tokenizer、配置和卡片均按修订与 SHA-256 校验；推理时不联网，不加载远程 Python 代码。权重及缓存不提交 Git。encoder 转换仓库声明 Apache-2.0；reranker 转换卡片未声明独立许可证，上游 cross-encoder 模型元数据声明 Apache-2.0，清单分别记录，没有把缺失声明补写成已声明。

索引编码记录 593 个输入、28 个截断输入、75 个批次。每次查询记录编码/重排输入数、截断数和分阶段时间。原文和引用完整保留，截断只描述模型实际输入；它不是压缩后的可靠原文。模型输出须有限、维度一致且非零；超长重排 query 在推理前拒绝。

## CLI、HTTP 与追踪

`python -m retrieval build REQUEST.json` 生成哈希索引、Qdrant 组件及不可变服务配置路径，重复相同构建复用相同工件。`search REQUEST.json --index DIGEST` 保存完整结果与轨迹，控制台只输出摘要/工件索引。`expand REQUEST.json --index DIGEST --document-id ID [--include-related]` 从原字节重放引用及上下文。

`app.retrieval_api:create_retrieval_app` 从 RECALL_RETRIEVAL_CONFIG 读取服务器配置；路由为 POST `/retrieval/search`、POST `/retrieval/expand`。服务器固定索引和本地模型，客户端不能指定路径或下载模型。每次响应携带轨迹工件索引，原始结果位于忽略目录。模型/本地存储不可用为 503，来源越界为 403，完整性失败为 409，错误输入/构建不匹配为 422；成功请求仍须检查 retrieved/partial/no_matches。

轨迹保存逐来源通道与原因、各通道 BM25/dense/RRF/rerank 候选排名/分数、返回块及等价位置、模型身份与截断、构建 ID 和耗时。不泄露服务器选择之外的文档 ID。

展开会重新核对请求范围和来源，而非信任之前的排名；为焦点、父块和必需上下文分别生成可回放引用。关联展开仅跟随已审查官方显式引用，并继续施加同一来源/车型范围；越界关联不展开，不能把显式引用当因果证明。

## 开发评测与复现

四个新召回事件、12 个英语开发问题在第一次语料排序前完成标签。qrels 以去重证据组为单位，3 为直接回答字段，1 为同事件背景，其他组为 0；由实现代理审查，不冒称独立人工金标准。固定参数、候选上限、指标和默认策略保存在协议。原探索资料只作干扰项，未见测试集未建立。

比较 Recall/nDCG@1/5/10、指定年份查询的错误年份命中、四条精确编号查询命中和本机预热时延。每种方法预热一次，每题测三次，以每题中位数汇总；模型加载/建索引不计入查询时延。只有 4 个独立事件，不报告有泛化含义的置信区间。

先完成 NumPy 参考路径，回查推荐技术栈后补齐 Qdrant；后端修订单独记录，标签、数值参数及默认判断门槛未因结果调整。Qdrant/参考分数在真实向量上对账，最终结果以 Qdrant 报告为准。早期参考运行和与回归并发的时延观测分别保留，不能当成最终后端的正式时延。

复现源文件时使用公开的原始获取清单：新下载须与旧字节哈希完全相同，才可导入旧项目获取记录；新请求仍保存当下真实观察。导入清单不构成独立早期归档。当前资料若已变更，应报告无法精确重现并建立新版本，不能改旧引用或旧标签冒充一致。
