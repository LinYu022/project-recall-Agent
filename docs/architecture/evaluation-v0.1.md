# 综合实验与失败归因 v0.1

P1-16复用P1-00～P1-15，不增加调查权限。数据、任务、模型配置、运行额度、记忆前缀和评分规则先固定；一次执行留下完整分母、逐任务原记录、真实输入/响应与失败。正式评测不是把之前开发结果汇总后改名为测试。

## 实验对象与冻结

`evaluation/contracts.py`定义Case、Arm、Protocol。主比较为相同60任务和相同上限的fixed/single_agent/parallel_tools/multi_agent；检索、上下文和两种记忆设置分别作为独立消融族，只改变相应因子，不展开全组合。协议拒绝任务列表/重复次数不一致、跨split事件复用、已见campaign伪装测试、同一campaign分进多个簇或主方法暗加上下文/记忆能力。

数据为本轮20份新获取的官方快照，另保留既有开发来源作为系统公共背景。主任务60，额外顺序序列2步，总270运行单元；每个单元包括方法、任务、重复序号及事件簇。重复次数1，不能报告随机波动已被充分估计。20个campaign按成对查询关系及已知Mazda关联保守合成10个统计簇；不声称发现全部现实事件关联，也不把新任务当作模型预训练未见知识。

引用标签由实现代理在真实生成前按原始记录构造，独立人工未审核。允许来源、请求与范围可给生成模型，reference slots/required_claims/可接受输出/评分/审查者不能给模型或写入记忆。模型发送器递归拒绝这些标签键和凭证键。普通来源正文仍是不可信数据，无法赋予新工具或权限。

`freeze.seal()`把协议、记忆前缀、代码/锁文件哈希、全部运行单元及请求上限放入不可变工件，内容哈希作为experiment_id，同时绑定Git实现提交。`load()`在运行前重核实现指纹；代码变化需要新冻结。已有实验、旧失败、旧审查不覆盖，先前准备冻结没有调用模型。

## 执行与请求额度

`CellExecutor`使用真实TaskControl、Dispatcher、Worker和共享根预算。四方法均不绕开授权；多Agent分支从同一根额度分配。条件/时间缺失由服务进入WAITING_INPUT，不能把未执行包装成调查完成；这些guarded单元也保存问题与盲审包。原报告不可变，语义评分另行导入。

`RunRecords`在开始前建全270格，状态有not_started/running/completed/guarded/failed/unknown。先claim落盘再执行，重复运行不会重新领取非not_started格。进程意外中断保留running/unknown，不猜测从未发出请求。不自动重建顺序记忆的新历史来续跑第二步；该情况保留未解决，需基于原数据库/工件显式处理，不能暗中重发前一任务。

本批ProviderLedger固定路径`.local/P1-16/provider-request-allowance.json`，绑定本批冻结身份/各单元额度/模型。换实验目录不能重置本批总额度。单元上限来自冻结协议：普通自然任务fixed最多1、其他方法最多8，预先规定的无生成护栏为0；总计584，失败/未知也消耗。累计输出最多4000tokens/单元，未知usage按已预留max_tokens记账；不自动重试。

`MeteredModel`先落输入哈希并预留，再发API；响应或错误留工件，含reported_model、usage、耗时及错误。API头由本机适配器认证，payload不带密钥。价格未核验时货币费用保持null；无请求的护栏可显示0个请求，但不能推导整个本地流程零开销。

`python -m evaluation`提供freeze/run/analyze/review-template/import-review；`scripts.run_evaluation_local`使用专用本地PostgreSQL，隐藏启动窗口，私有密码仅留忽略目录，正常结束停止服务。数据库保留用于审计/显式续跑，和测试临时schema清理不同。运行目录按实验和scripted/live隔离。

## 记忆状态与时序

四级为none、semantic、semantic_episode、all。每个冻结单元创建独立用户/项目，从同一声明和先期范围检查规范重建；none也有相同先期历史但不选入生成。先期脚本只返回不足，没有目标问题的答案或评分标签。初始scope经历在目标创建前完成，运行时历史筛选继续检查owner/project、允许来源、年份、版本和提交时间。

冻结历史设置每格重置。顺序设置每方法/重复序号重置一次，再按固定两步顺序执行；第二步可看到本方法先前任务的经历。方法形成的历史可能不同，因此顺序比较是系统整体比较，不能称为相同固定历史下的纯检索增益。

只有all组构造并验证程序性Skill；非Skill组不应因这一步失败而被阻断。Skill源于两个旧来源的可回放范围流程，在第三个目标范围流程迁移验证。目标范围元数据未知时验证可能失败，这属于实际前置条件限制，保留失败和证明；不强制启用。所有准备的真实工具/脚本调用单列，setup_ms计入端到端耗时，真实provider额度仍独立约束。

## 统计、审查与图

`analysis.py`要求完整冻结分母，未运行/失败保留。按case+重复序号配对，再在事件簇内平均、簇间等权平均，固定随机种子做2000次簇bootstrap。少于5簇或缺配对不报区间；重复运行不增加事件数。2任务消融的区间通常为空，报告逐题差值和局限。

完成执行、引用原文回放、标签槽覆盖均属机器检查，不等同任务完成率。独立审查逐条检查引用—结论对，partial单列；不完整、not_evaluable或待决争议保持null。关系判断必须覆盖预定关系义务，不能少写关系就提高精度。任务成功需独立审查、全部必需事实/条件、足够证据组合和正确处置同时满足。

`review.py`把审查绑定精确observation/report/reference哈希；实现代理和合成判断只可provisional，不能变成formal。未填写模板不预填human。新证据仍按P1-07的独立审查与版本修订规则接受；审查修改保存新工件，不改原响应。审查者应只拿public盲审包，不拿private映射、方法或既有分数。

图使用锁定开发依赖matplotlib导出PNG/PDF。质量—费用坐标在缺审查/价格时明确留空，并展示执行状态分母；不把null画成0。端到端时间包括准备、执行、评分导出等本机工作，人等待单列；调查器内部elapsed与完整耗时不得混用。

## 故障与可信边界

自然任务与`challenges.json`分别统计。挑战包括晚到记录、未来修订、发布更新、错误关联、外部来源文本、旧授权、旧worker，以及正常/保存后崩溃恢复/关闭恢复/未知模型输出。触发阶段按语义命名，并要求测试实际触发；未触发不能计成功。恢复后的执行交付、安全停止及独立判断正确的答案分开。

本轮故障是同进程InjectedCrash；没有冒称新增独立进程强杀。外部文本挑战把恶意字符串放入明确合成的来源记录，再用脚本模拟遵从它的模型，验证有限动作契约在越权操作前拒绝；这不证明任意真实模型或未知提示注入都安全。

## 保留的限制

新来源的品牌/车型映射覆盖不足会产生pending通道和范围验证失败；评测保持已冻结规则。这是需要报告的系统能力边界。证据Recall的gold来自原始引用单元，不能先用系统匹配状态过滤gold，否则把过滤失败从分母中消掉。检索原始分级标签由实现代理构造，语义等价新证据须独立复核。

模型使用deepseek-flash服务别名，provider_weights_revision未知，不能声称已锁定服务端权重。正式生成的结果、代价与人工待审状态由机器摘要和原工件给出；独立质量指标缺失时保持待审，不宣称机制收益。P1-17～P1-18继续保留。
