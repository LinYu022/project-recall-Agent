# P1-14：情景记忆、历史搜索与事件浏览

本模块依赖P1-13的用户/项目空间、开关及审计，复用既有固定发布、报告工件、授权和持久worker。情景记忆保存“某次调查做过什么”，不晋升为新的领域事实或可执行Skill。

## 数据与投影

0008迁移增加`memory_episodes`、`memory_episode_events`和`memory_episode_adoptions`三张表。快照绑定owner/project、来源任务及版本、修订/授权、release、范围、时间口径、报告工件引用和原始事件投影；ID与内容哈希可复核。一个任务状态版本在同一用户/项目中只捕获一次，重复调用幂等。

投影是确定性抽取，不调用摘要模型。保留生命周期、各执行代次、工具尝试/状态、假设变化及反证、分支/冲突、终止原因、结果类别和未核实项。旧回答正文、最终claim.statement不进入历史摘要或模型历史上下文。假设的supported/contradicted仍是旧模型提议，不是人工语义金标准。

生命周期按原control.version排序；报告中的工具数组、规划修订数组等按原记录顺序分段索引。旧报告缺少统一绝对时间，本实现明确使用`recorded_section_array_order_not_wall_clock`，不把拼接数组宣称为精确的并发墙钟时间线。锚点窗口沿这个可复现逻辑顺序浏览。

默认概要给出问题、范围、版本、尝试、失败标签、反证数量和被否定假设，并提供事件锚点及少量历史来源句柄；不返回完整聊天或旧结论正文。API可跨任务搜索、按任务筛选事件、最近任务分页、按事件ID查看前后窗口。原文分页通过服务器登记的报告/证据ID定位，不接收文件路径或任意工件哈希。

## 捕获与一致性

Plan可用`project_id`为本任务登记归档项目，也可通过显式history配置开启历史采用及归档。三类项目字段（project_id、memory.project_id、history.project_id）必须一致。旧计划默认都不捕获历史；单独的P1-13语义记忆配置不会自动开启历史捕获。

正常完成和显式失败的报告在正式状态提交事务中尝试捕获。可选索引失败通过保存点回滚索引写入，正式调查保留，另记`history_capture_failed`及quality.history_index=failed；不会默认为空历史。授权/项目被停用时不新增可用历史。已终止或中断的旧任务也可由所有者显式`/history/capture`，不会后台猜测项目归属。

快照不是权限凭证。每次检索/浏览重新核对来源任务当前修订、授权、父任务边界及原报告工件；来源任务修改或授权撤销后旧快照失效。原报告丢失/损坏或索引与快照不同则明确报错，不能静默用缓存替代。历史启用/停用有修订检查及审计事件，采用后的停用会阻断当前任务发布。

## 先筛选，再相关度排序

检索先限制owner和项目，核验全局/项目开关；再过滤车型、年份、生产/配置等范围及允许来源。make/model/model_year要求相同，缺失也不自动当作相同；其他约束只允许当前范围收窄历史范围。相同车型、相似症状但不同年份不会进入排序集合，更不会占用top-k后再被删除。

默认要求同一release；显式allow_cross_release只允许历史线索进入，不能搬运旧证据。任务内采用固定当前允许来源、范围和时间口径，且历史发生时间不晚于当前任务首次提交时间；恢复时也沿用该边界，排除后来完成的任务和自身任务。时间口径不同的记录不用于自动采用。

在合格集合中，使用中英文词项重合度按症状/失败信息排序，稳定ID作并列次序；最近浏览按捕获时间及ID排序，游标必须位于当前可见集合。当前没有向量历史检索收益或跨用户相似度搜索结论。

## 调查采用与工具

`Plan.history={project_id, enabled, allow_cross_release, limit}`默认None，启用或换项目经原精确审批；默认初选最多3条，每执行累计最多8条。历史输入使用原上下文/生成额度，没有额外预算池。

四类方法都能得到有界history_context。固定流程使用初选线索并继续当前固定查询；单Agent和两个调查分支还可选择history_search/history_window，分别消耗普通工具额度。工具返回导航观察，不创建E证据卡；不能把EP/HE/历史证据ID当作当前E别名。

初选摘要不因其他分支浏览而变化；工具结果留在各分支自己的观察/工件中，累计采用ID由父执行统一审计。重放历史搜索输出后仍会校验并登记采用，避免“响应已保存但采用状态尚未更新”导致恢复丢失。重复动作受原有次数限制，导航仍可能耗尽工具/模型预算。

初选是一项服务端上下文准备工作，报告单列history_preparation.seed_searches及elapsed_ms，不计作模型选择的调查工具动作；后续history_search/window逐次计普通工具额度。初选延迟不包含在调查器内部total_elapsed_ms中，不得将其当成免费或用于漏计开销的性能比较。采用记录表示选入本执行的线索，不证明它实际改善了回答。

生成前、持久步骤前后和发布前都检查采用项仍有效；发布还要求当前报告具有已验证的当前release结构化lookup，旧历史ID不会变成当前证据。当前业务工具和verify_cards继续回放原始字节；历史不替代当前检索或原文验证。任意自然语言推论是否真的由当前证据支持，仍须独立语义审查，不能由哈希检查自动证明。

原报告保存history_usage，读取时追加history_audit显示源授权/启用状态是否变化，不修改原不可变报告。停用或授权撤销不假装远端调用已停止；在途响应可私有保存，不能被失效执行发布。

## 原文回查边界

历史原文仍属于旧release。回查先核验当前调用者、项目、历史范围/来源、来源任务活跃授权，再完整校验旧发布及数据库投影，重放旧报告的引用和必要上下文。旧release绑定已关闭时，内部只读适配器只接受已核验的那一个绑定；该入口不能执行任务、扩大来源或接收外部路径。

返回结果明确`historical_source_only=true`。要把事实写入新报告，仍须通过当前任务的真实工具重新取得当前E证据并校验。原发布不可用时明确失败；相似历史的存在不等于当前事实成立。

## 接口与限制

认证API提供`/history/capture`、`/search`、`/recent`、`/events/search`、`/events/window`、`/source`及`/{episode_id}/state`。API查询条件是已认证用户对自己历史的筛选；Agent工具条件从已批准的当前计划构造，模型只能给症状词或已有锚点，不能提供owner/project/来源/范围。

数据库与工件无共同事务；投影/工件问题可能阻止回查或采用，必须保留错误。没有共享团队项目、通用语义类比证明、真实新模型质量收益或精确并发墙钟回放的承诺。计划完整目标保留；程序性流程晋升留在P1-15。学习与实验见[P1-14记录](../learning/P1-14.md)。
