# P1-13：语义记忆、候选审核与撤销传播

本模块依赖P1-10的上下文与工件、P1-11的持久执行；调查器沿用P1-12。记忆是可撤销的偏好/约定/操作提示及来源索引，官方事实仍由固定DatasetRelease中的业务证据证明。

## 权威层级与契约

| kind | 可进入活动记忆 | 晋升条件 | 使用边界 |
| --- | --- | --- | --- |
| preference | 可以 | 已认证的用户声明来源及针对精确候选哈希的审核 | 用户或项目范围的表达偏好，不改变调查结论 |
| convention | 可以 | 用户声明及明确审核 | 仅项目约定，不能授予工具或扩大来源范围 |
| rule | 可以 | 用户审核、已安装规则的可执行检查、固定发布/来源校验 | 当前只支持两条已实现的保守操作规则 |
| source_pointer | 可以 | 用户审核、发布及来源/可选记录版本存在性校验 | 只保存来源入口，不复制官方事实文本 |
| official_fact / hypothesis | 仅候选 | 禁止晋升 | 事实回到业务证据，推测保留未确认状态 |

`memory/contracts.py`严格限定scope、project_id、semantic_key、适用车型/条件、release_id、来源指针和带时区的expires_at。领域规则/指针必须绑定项目、发布和来源，value为空，由程序生成固定提示；不能在指针中塞入一段官方事实。规则只接受安装表中的policy_id：使用前回放原文，或缺少个车生产日期/配置时保留未知。

`memory/policies.py`执行有界行为检查，并记录规则及相关实现的指纹：一项调用现有前置条件检查，另一项验证只有哈希而没有原文时证据校验拒绝。它们支持的是已实现操作约束，不是任意自然语言领域规则的语义正确性证明。新增规则需先实现、测试并版本化，不能让候选文本自行注册可执行代码。

## 持久数据与队列

0007迁移增加10张表：用户状态/代次、项目、来源、候选、活动记录、派生索引、缓存、提取队列、审计事件、任务采用记录。迁移固定DDL，不依赖未来Python表定义；0006及之前数据保留。

```mermaid
flowchart LR
  S[已认证声明或不可信导入文本] --> Q[持久提取队列]
  Q --> W[独立提取进程：有界声明解析]
  W --> C[待审候选：精确哈希、来源、作用域]
  C --> R[用户审核及程序规则/来源检查]
  R --> M[活动主记录]
  M --> I[派生检索索引与引用缓存]
  I --> T[显式启用记忆的调查任务]
  M --> D[删除/停用/替换/过期]
  D --> I
  D --> G[生成与正式发布前再次校验]
```

当前提取器读取JSON声明`{"memories": [Proposal, ...]}`，每源最多20000字符、每批1～8条；严格解析后只创建候选。它是确定性的声明提取器，不调用LLM、不从自然语言自动猜测事实。后台进程`python -m memory`与任务worker分开。入队不会同步执行；同一来源重复入队幂等，候选按来源/内容指纹去重。

提取工作全部在一个有界数据库事务内完成，候选与job一起提交；崩溃回滚后保持queued，重启可再次领取。行锁/SKIP LOCKED防止两个提取者同时消费同一工作，catalog事务锁也会串行化本地生命周期操作。这个协议依赖“没有外部调用”；未来引入模型提取必须接入P1-11的预留、未知响应及租约协议，不能简单把网络请求塞进该事务。

不可信导入文本即使写着“用户已确认”，origin也仍为untrusted_text。重复摘要可以重复出现同一候选，却不能转为user_statement或批准记忆。需要用户另行声明并审核。接口身份来自现有Bearer映射，JSON不能指定owner，也不能靠来源文本进行审核。

## 审核、冲突和更新

审核提交expected_revision与proposal_sha256，拒绝陈旧/重复审核。同一owner、scope、project、kind、semantic_key是一个冲突槽；已有活动记录时不能静默覆盖，必须明确replace_memory_id。编辑创建新候选，并固定被编辑记录的修订；审核期间旧记录变化则停止。

晋升事务同时保存审核身份/时间/说明、程序验证证据、活动主记录、索引与审计事件。替换会把旧记录置superseded；停用、删除或过期增加修订并移除活动索引。所有这些变化推进该用户generation并清空用户缓存，其他项目中的用户级记忆也不会留旧缓存。索引/缓存是派生物，永远不能晋升主记录。

“删除”表示立即停止活动检索及新任务使用；来源、历史事件和旧报告保留审计，不是物理擦除所有历史字节。已删除记录不能直接启用，纠错需新声明/候选/审核。停用后若要恢复，也经候选与重新审核；命名空间或项目开关则支持明确开启/关闭。

## 检索与缓存

项目由已认证用户登记，只允许该owner访问；当前不实现团队共享项目。用户级偏好可在同一用户拥有的不同项目使用，项目级内容不能跨项目。读取个别记录、历史、候选与提取job也检查owner。

先检查用户和项目开关，再按owner、项目、适用车型/条件、release_id、允许来源及过期时间过滤；同一kind/semantic_key的项目值覆盖用户级通用值，然后才作有界词项相关度排序和截断。此处“语义记忆”描述记忆种类，检索目前采用可解释的中英文词项匹配，不宣称语义向量召回效果。排序不先访问其他用户内容再事后删掉。

缓存键含owner、generation及完整查询条件，缓存只存记忆ID/修订。命中仍核对主记录、审核来源及适用条件，领域条目还重新验证冻结包/来源和已安装规则指纹。旧缓存即使误恢复，也不能复活被删主记录。过期按数据库时钟处理，在检索/读取/审核相关路径惰性清理索引；没有请求时过期行可能仍物理存在，但任何返回或采用都检查时间。

每次检索、生成输入前和发布前均完整核验领域来源；同一次检查内的相同发布只核验一次，校验结果不跨事务保存。每个日志步骤前后另行检查活动主记录、修订、审核与声明来源，避免重复校验整个冻结包。开发首轮的重复校验在真实演示中开销较大，调整记录见实验文档。没有将缓存命中当作来源仍有效的证明，也没有宣称生产吞吐或性能收益。

## 调查接入与撤销

Plan新增可选`memory={"project_id": "...", "enabled": true}`，默认None；授权边界保存相同配置。启用或换项目需要现有精确计划审批，关闭是权限收窄；提交时校验项目归属。所有方法可注入相同记忆协议；多Agent的线程继承相同只读采用快照，仍独立规划。

每次执行按当前允许来源、固定发布和问题选择最多8条，记录采用ID/修订/哈希到数据库，并加入`memory_context`。记忆的输入占用原上下文和资源额度，不额外分配。协议明确记忆不能成为E证据、不能改变工具/授权/来源/未知条件；已有证据Schema/引用护栏继续拦截将M记忆ID当证据。

生成输入构建前、持久步骤前后、正式发布事务内都重新校验已采用记录。执行中若删除、停用、替换、过期或来源不再适用，该执行停止/暂停，不能发布引用旧记忆的报告。在途provider不能硬取消，响应可私有留存与结算。新任务重新检索，不能沿用历史报告的记忆清单。

恢复同样重建当前记忆输入；已完成响应只有在实际输入指纹相同时才可重放，改变记忆不会让旧响应被悄悄采用。当前选择集变化可能导致严格恢复失败，需要明确新任务/修订；不承诺在记忆变化后自动继续。

报告保存不可变memory_usage及采用时状态；读取报告附加memory_audit显示各条当前主记录状态。删除不修改旧报告工件，也不伪装旧报告从未使用过该条。该状态不是对历史回答语义质量的重新评分。

## 接口与边界

认证API新增`/memory/projects`、`/settings`、`/sources`、`/candidates`及审核、`/search`、`/items/{id}`及change/edit/history、`/extractions`及job查询。用户设置用expected_generation，记录变化用expected_revision，候选审核另有内容哈希。学习文档提供可运行范例。

自然语言提取、任意规则的自动证明、团队协作ACL、向量召回优化、历史事件搜索与Skill晋升均未冒称实现。后三类完整目标分别留在后续模块；当前候选提取、审核、CRUD、失效及调查接入均真实运行。验证分类及限制见[P1-13实验](../experiments/P1-13-memory.md)。
