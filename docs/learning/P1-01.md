## 第一步：从文档约定到可执行规则

数据流：

`JSON 文件 → CLI 读取 → TaskSpec 字段校验 → 嵌套时间与跨字段校验 → 最小状态输出 / 非零退出码`

关键代码在 `domain/tasks.py`：

```python
@model_validator(mode="after")
def required_business_conditions(self) -> Self:
    if self.status == "ready" and self.release_id is None:
        raise ValueError("ready tasks require release_id")
    if self.task_kind == "complaint_statistics" and self.time.event_interval is None:
        raise ValueError("complaint_statistics requires an incident event_interval")
    return self
```

`mode="after"` 表示字段解析成功后，再检查字段之间的业务关系；`Literal` 限定模式；`AwareDatetime` 要求时区；`extra="forbid"` 阻止错误字段被忽略。日期先解析为日期对象，再比较大小。[Pydantic 官方模型说明](https://docs.pydantic.dev/latest/concepts/models/)及[校验器说明](https://docs.pydantic.dev/latest/concepts/validators/)。

领域契约不导入 HTTP 或数据库组件，因此 CLI、后续 API 和 worker 能复用规则。当前还未实现授权；文本字段通过校验不表示内容可信，声明一个 grant_id 也不表示授权存在。

## 环境与复现

`pyproject.toml` 声明依赖范围，`uv.lock` 固定本次实际解析的版本及包哈希；提交锁文件，不提交虚拟环境。[uv 锁定与同步说明](https://docs.astral.sh/uv/concepts/projects/sync/)。

本次实际环境：Python 3.12.14、uv 0.11.26、Pydantic 2.14.1、pytest 9.1.1、jsonschema 4.26.0。支持范围暂为 Python 3.12；未宣称其他 Python 或操作系统已验证。

在项目根目录执行：

```powershell
uv sync --locked --python 3.12
uv run --locked python -m app validate-task evals/exploration/tasks/EXP-001.json
uv run --locked python -m pytest -q --basetemp .local/pytest-tmp
```

正确任务预期输出 `status=valid`、`task_id=EXP-001`、`check=contract_only`，退出码 0。`contract_only` 明确校验边界，不把格式正确误报成调查成功。

当前机器的 `python` 命令指向不可用的商店别名，实际用已发现的 Python 3.12 解释器建立了虚拟环境。文档复现不依赖该机器绝对路径。

## 练习及参考答案

练习：复制 EXP-001，保留 `release_id=null`，仅把 `status` 改为 `ready`；预测结果再运行校验。参考答案：拒绝，退出码 2，错误为 `ready tasks require release_id`。

可直接执行的范例，在项目根目录的 PowerShell 7 中运行：

```powershell
New-Item -ItemType Directory -Path .local -Force | Out-Null
$practiceTask = Get-Content evals/exploration/tasks/EXP-001.json -Raw | ConvertFrom-Json
$practiceTask.status = 'ready'
$practiceTask | ConvertTo-Json -Depth 10 | Set-Content .local/invalid-task.json -Encoding utf8NoBOM
uv run --locked python -m app validate-task .local/invalid-task.json
$LASTEXITCODE
```

再把模式改为 `historical_as_of`，仍不提供截止时间，也会拒绝。反过来，填入任意非空 release_id 可能通过这一步校验；这不证明发布存在。未来执行层必须查询发布注册表，不能依赖输入自行声明。
