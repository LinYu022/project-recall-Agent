## A：保留文本，先明确坐标系

`parsing/parser.py` 使用已锁定的 pypdf 6.21.2 layout 模式，保留页文本的空格、换行和脚注，不做大小写、断词拼接或空白折叠。原 PDF 仍保存在按原始字节哈希寻址的 objects/ 目录。

每个 PDF 页形成一个 text unit，page_number 从 1 开始；按空行提出 region 候选，ordinal 从 0 开始。候选区域不是已经验证的语义段落或检索块。表格只保留布局文本，不自动解释单元格。JSON 投诉保留整个 summary 字段，召回的 Summary/Consequence/Remedy/Notes 各自保留，引用能回到对应原行字段。

```python
quote = unit["text"][start:end]
```

start/end 是解码后 Python 字符串的半开区间 `[start,end)`，不是 UTF-8 字节位置或 PDF 内部坐标。`café 🚗` 的字符数与字节数不同；新增测试验证了这一点。PDF 页上的视觉位置仍需对照原页，不把字符偏移冒充图像框。

空行区域只修剪区域边界，不改父页字符串；每个区域保存 parent_unit_id、起止位置和区域文本哈希。引用因此可以跨多个候选区域，完整性判断留给后续语义校验。

## B：内容、解析方法与引用分别固定

ParsedSource 保存 source_version_id、源内容哈希、raw_sha256、原 URL、快照和原文相对路径。解析方法另记 parser_version、配置、pypdf 版本、是否 OCR 和 parser_sha256。JSON 字段使用 stdlib_json 复制，不冒称由 PDF 引擎解析，也不因 PDF 库升级而改变该字段回放结果。

工件复用 ArtifactStore 的 SHA-256 文件存储：相同结果重复保存不变，不按 URL 覆盖旧文本。引用固定解析工件哈希、原始版本、页/字段单元、文本哈希、偏移、原样摘录和摘录哈希。原始数据库中 P1-02 的 text_parse_status=not_started 仍是当时的映射产物；新解析状态位于派生工件，不改写旧记录。

`checked_parse` 先验证工件内容哈希，再从原始快照按记录的方法重放；`resolve_citation` 比较来源、单元、边界及摘录。PDF 回放要求记录的 pypdf 版本，版本不一致时拒绝静默重解析，使用相应锁文件/实现版本恢复环境。没有将新版库的输出替换旧引用。

```python
actual = unit["text"][citation.start : citation.end]
if actual != citation.quote:
    raise ArtifactIntegrityError(...)
```

验证结果是“出处和位置一致”，不等于该引用语义上支持某个结论，更不等于完整调查已完成。正式 DatasetRelease 仍待 P1-06 绑定。

## 范例、练习与参考答案

在本机固定快照上运行，不需要数据库：

```powershell
$parsedResult = uv run --locked --offline python -m parsing parse 9d2d065bf1f844e7ab4ea63494a4b2f9 | ConvertFrom-Json
$parseDigest = $parsedResult.parse_artifact.sha256
uv run --locked --offline python -m parsing cite $parseDigest --unit 0 --find '10V-039' --output .local/my-P1-04-citation.json
uv run --locked --offline python -m parsing verify .local/my-P1-04-citation.json
```

参考答案：parse 返回 parsed、1 页、1 单元、9 个候选区域；cite 返回精确摘录和位置；verify 返回 verified、page_number=1、start=2227、end=2234。--output 文件不能覆盖；重复练习换新文件名，或直接验证已保存文件，原引用不变。

真实资料完整回放：

```powershell
uv run --locked --offline python -m scripts.verify_parser
```

参考答案：pdf_pages=1、citations=2、complaint_fields=103。原始字节必须保留；其他机器先 capture，并用脚本的 --pdf-snapshot、--complaints-snapshot 指定自己的 ID。相同 URL 后续可能变更，不假装能下载出同一历史字节。

以下练习已用合成字节/可控故障测试实现，直接给参考答案：

| 场景 | 参考答案 |
| --- | --- |
| 修改引用中的 not / 范围词、摘录哈希或位置 | 拒绝验证；不能只检查引用 ID 是否存在 |
| 相同 URL 出现新 PDF 内容 | 生成新记录版本；旧引用仍从旧快照回放 |
| PDF 库版本发生变化 | 不静默替换旧解析，要求对应环境；纯 JSON 字段不依赖该库 |
| PDF 没有可提取文本 | needs_review_or_ocr，不是成功空文本；不猜 OCR 结果 |
| PDF 第一页提取失败，第二页成功 | partial；成功页仍编号 2，不重编号为 1；默认禁止生成完整可信引用 |
| 加密/损坏 PDF，或页数/文本上限超出 | failed，保留具体代码；不把截断内容当完整文档 |
| --find 出现两次 | 拒绝选取；不能悄悄用第一次出现的位置 |
| 篡改原始对象或解析工件 | 哈希/重放失败，拒绝引用 |
| 文本中出现额外指令或伪造批准话语 | 作为原始文本保留；解析器不执行文档内容 |

```powershell
uv run --locked --offline python -m pytest -q tests/test_parsing.py --basetemp .local/practice-parsing
```

参考结果：24 项解析/引用测试通过，全部使用合成内存 PDF、JSON 或明确注入的故障。没有将这些测试样例称作真实扫描件/OCR 实验。
