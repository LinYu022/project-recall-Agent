## 本模块目标与依赖

依赖 P1-00 的真实探索来源与任务边界，以及 P1-01 的领域契约、哈希工件和可复现检查。本模块建立可回放的来源版本，供 P1-03 实体查询、P1-04 文档解析和 P1-06 一致发布使用。没有固定原始版本，就无法解释某个结论依据的是哪次下载。

按原计划保留全部产物：原始快照 manifest、字段字典、时间映射表、数据质量报告、资料可用性矩阵；验收包括幂等导入、记录数对账、不可覆盖的新版本，以及 historical_as_of 的过滤与拒绝。

分成三小步，避免一次写完：

1. 原始字节与获取清单：本轮实现召回、投诉、调查 PDF 的获取和回放。
2. 结构化记录导入：核对字段字典，设计来源 ID/内容版本、数据库迁移、幂等导入与时间映射。
3. 更新与验收：迟到记录、历史修订、未知公开时间、资料可用性矩阵和质量报告；真实资料与受控测试分别记录。

本轮未进入 P1-03，未将真实资料接入仍为模拟模式的调查 demo。

## 必要原理：内容身份与获取事件

一个 URL 可以在不同时间返回不同字节；相同字节也可能被下载多次。因此分别保存：

| 身份 | 生成方式 | 表示什么 |
| --- | --- | --- |
| source_id | 来源注册表固定标识 | 本次请求的来源与筛选范围 |
| 原始对象 sha256 | 对响应 body 原字节计算 | 一份具体内容；不是重新排版后的 JSON |
| snapshot_id | 每次请求生成 UUID | 一次获取尝试，包含时间、响应与验证状态 |

目录为 `.local/source-snapshots/objects/<sha256>` 和 `snapshots/<snapshot_id>.json`。相同字节复用一个对象，获取清单仍新增，既不重复占用内容存储，也不丢掉观察历史。失败也保存独立清单；有完整响应时保留错误 body，网络中断/超限时不把截断内容发布成完整对象。

原始快照不是 P1-06 DatasetRelease，也不证明正式统计全集完整。当前三个来源沿用已经看过的探索事件，仍标 `exploration_only`，不加入未见测试集。

## 第一步 A：显式来源选择

`examples/nhtsa-sources.json` 保存来源 ID、类型、完整 URL、筛选条件和单响应上限。`ingestion/sources.py` 只加载该注册表，限定已核对的官方 HTTPS 主机。CLI 接受 source_id，普通任务文本不能改变采集地址。

来源选自 [NHTSA 官方数据与 API 目录](https://www.nhtsa.gov/nhtsa-datasets-and-apis)：召回支持按 campaignNumber 查询，投诉支持按 make/model/modelYear 查询。当前只请求明确的小范围样例，未下载批量全集，也未把车型筛选说成制动主题筛选。范围扩展与批量策略留在本模块下一步继续设计。

调查 PDF 使用 P1-00 已核验的官方 PE10006 结案文件。这里仅获取字节和检查 PDF 文件头；结构解析、页码定位及内容质量在后续实现，不把 `%PDF-` 检查称为 PDF 已成功解析。

## 第一步 B：保存原字节，区分失败

核心代码在 `ingestion/snapshots.py`：

```python
digest = hashlib.sha256(body).hexdigest()
with (directory / digest).open("xb") as stream:
    stream.write(body)
```

`xb` 创建新文件；已有对象不覆盖，先重新检查哈希和长度。存储损坏时明确报错，避免继续沿用坏工件。读回使用相同的字节哈希；不会先 JSON 解析、再重新编码冒充原始响应。

网络传输使用 Python 标准库，单次读取最多上限加一个字节，30 秒套接字超时，无自动重试；重定向作为非 200 响应记录，需要人工核对后更新注册表。若服务器提供 Content-Length，核对实际长度。这个超时不是严格的总下载时限；当前不支持压缩解码、断点续传或多线程采集。

| 状态 | 含义 | record_count |
| --- | --- | --- |
| captured | HTTP 200，完整 body，通过容器检查 | API 返回条数；PDF 为 null |
| http_error | 完整收到非 200 响应 | null |
| transport_error | 超时、断连、不完整响应等 | null |
| too_large | 超过显式字节上限 | null |
| invalid_payload | JSON/计数/行结构或 PDF 文件头不合格 | null |

召回 API 用 `Count`，投诉 API 用 `count`；都要求非负整数、results 数组及条数一致。`captured + record_count=0` 是成功空结果，与网络失败的 null 不同。检查通过不代表每个业务字段都正确，逐条字段校验和失败行隔离在第二小步。

真实投诉原文与 VIN 留在忽略目录；命令输出和公开观察清单只包含获取元数据，不输出投诉内容。磁盘错误直接抛出，不伪装成网络失败。当前文件写入不具备多文件事务或崩溃恢复承诺；哈希可以检测损坏，不能验证来源签名或防止拥有写权限的人修改全部清单。

## 第一步 C：时间先保留证据，不猜日期

| 时间概念 | 本步处理 | 后续用途 |
| --- | --- | --- |
| 事件发生时间 | 原值留在原响应 | 投诉事件区间过滤 |
| 机构接收/提交时间 | 原值留在原响应 | 接收口径与迟到记录 |
| 内容版本公开时间 | `version_public_at=null` | 无证明就不能用于更早历史时点 |
| 本地请求/获取时间 | 带时区 UTC；request_started_at/completed_at/fetched_at | 证明本轮取得了哪些字节 |
| HTTP Date / Last-Modified / ETag | 原值保留 | 传输与缓存观察，不直接作为版本公开证明 |

`historical_evidence=local_fetch_only` 说明证据只到本次获取。重复抓取不会重写之前的获取时间；跨快照计算同一内容的首次观察、保存逐条 SourceRecord 时间和执行 historical_as_of 过滤均未在本步实现。

已知问题：召回 API 的 `ReportReceivedDate="09/02/2010"` 存在格式解释风险，不能根据字符串外观套用美式日期。投诉 API 的日期形态不同，也不能直接复用同一解析器。下一步核对官方字段说明与实际记录，再冻结逐来源的时间映射；本步保持原字节，尚未猜测 ISO 日期。计划无需删减功能，这里是落实计划所需的来源映射核验。

## 运行范例与练习参考答案

在项目根目录执行，capture 会联网：

```powershell
$capture = uv run --locked python -m ingestion capture NHTSA-API-CAMPAIGN-10V039000 | ConvertFrom-Json
$capture.status
$capture.raw.sha256
uv run --locked --offline python -m ingestion verify $capture.snapshot_id
```

参考结果：本轮 status=captured、record_count=2。snapshot_id 和获取时间每次变化；将来内容哈希也可能改变。verify 仅读取本地已保存清单和字节，不访问来源。capture/verify 成功退出码 0，已有获取失败清单退出码 3，未知 ID/文件损坏等操作失败退出码 2。

练习 1：相同内容获取两次，应该有几个文件？参考答案：两个获取清单，一个原始对象。执行 `tests/test_snapshots.py` 的 `same_bytes` 用例可观察受控验证；本轮也真实重复请求了一次召回，取得相同哈希。不要把“内容去重”说成“记录数据库幂等导入已完成”。

练习 2：计数声明 1，但 results 为空，或者 HTTP 503，是否返回 0？参考答案：两者均失败，count=null；前者 invalid_payload，后者 http_error。已有完整 body 保留供排查。成功的 `Count=0, results=[]` 才会得到 captured/count=0。

```powershell
uv run --locked --offline python -m pytest -q tests/test_snapshots.py --basetemp .local/practice-snapshots
```

练习 3：2026 年下载的 PDF 的 Last-Modified 标着 2022，能否用于 2014 年的历史还原？参考答案：不能由此证明。需要该内容版本在截止前已公开的可靠证据；本步不改写 version_public_at。后续会实现明确的过滤和拒绝机制，不是删去 historical_as_of。
