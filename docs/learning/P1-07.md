# P1-07：Claim/Evidence、评分与固定调查流程

本模块学习目标：把“有一段文字引用”拆成可核查的出处、适用范围、必要上下文和语义支持，做出后续 Agent 能公平比较的固定流程。前置为 P1-00 的任务与评价边界、P1-03 的实体/计数/关系工具、P1-06 的不可变数据发布。P1-04/05 的原文引用和检索通过 P1-06 进入本模块。

用户已选择按模块一次交付，练习直接附参考答案。本文完成后等待理解确认，再进入 P1-08；P1-00～P1-18 完整目标不删减。

## 必要原理

Claim 是一条可独立检查的结论，例如“冻结的2016 F-150投诉资料中，动力或制动标签对应86个去重ODI记录”。它还需要固定范围和引用，不能把“86条投诉”悄悄换成“86辆已证实存在缺陷的车”。

Evidence 是来自工具、可回到固定资料的事实。文字证据保存原文、字符位置和来源版本；计数证据保存结构化查询结果。引用检查解决“是不是这些字节中的这段话”；语义审查解决“这段话能否支持这句话”。两者都需要，不能互相代替。

一个结论可能需要多个证据共同成立。`[[范围, 条件段], [完整页]]` 表示两种可接受组合：第一种必须同时有范围和条件段；第二种可使用完整页。完整页引用可包含足够事实，但回答若没有说出必要条件，完整性仍未通过。

固定流程对工具调用顺序作预先规定，避免后续 Agent 只与弱检索摘要比较。它没有自主规划：先查条件和时间，再查全集、计数/关系、检索及必要展开，然后一次生成并校验。

## 关键代码与设计取舍

- `investigation/context.py`：经发布校验后枚举允许的全部记录版本。查询零、范围未知、没有相应来源分别处理，避免把 top-k 空结果解释为不存在。
- `investigation/evidence.py`：由服务器建卡，保存输出工件定位；从发布原始资料重建校验卡片，拒绝自哈希正确但事实伪造的卡片。模型用 E001 别名，原始哈希留在报告中。
- `investigation/flow.py`：固定至多6次工具和1次生成，按来源多样性展开。强制保留上下文，超预算失败留档；关联输出展示一次完整事实，避免同一段文字反复占用输入。没有自由回答字段。
- `models/chat_api.py`：真实 DeepSeek JSON 接口；本机凭证仅白名单读取。JSON 仍需要本地契约验证；截断和失败不会转换成成功答案。
- `investigation/scoring.py`：OR/AND证据组合和单独语义审查；未审字段为 null。`review.py` 导出隐藏方法/模型的包及本地私有映射。

例如 `verify_proposal()` 会要求焦点证据的 required_context_ids 出现在同条 Claim 的引用集合中。模型原始引用先由确定性步骤补齐已经展示的必要上下文，补齐清单另存，原始输出不覆盖，再通过严格校验。这能保证最终可用引用集合不省略强制范围上下文；它不能自动识别“永远安全”这类所有语义过强表达，所以还要读原文作判断。第二轮采用该策略；第一轮遗漏导致的拒绝保留在实验记录中。

完整设计和局限见 [架构说明](../architecture/investigation-v0.1.md)，标签/新增证据/争议规则见 [审查协议](../../evals/investigation-v0.1/README.md) 及 [v0.2原子参考修订](../../evals/investigation-v0.2/README.md)。修订发生在已看过的开发输出上，不伪称预注册实验。

## 练习与参考答案

练习一：构造“引用真实但结论过强”。

参考错误答案：“PE10006已经结案，因此所有混动车都不存在制动安全问题。”

原页的车型范围是 Model Year 2010 Toyota Prius，Summary 记录特定ABS制动条件、Toyota的召回措施、基于措施结案，以及ODI继续监测。出处真实不能支持所有混动车、缺陷不存在或永久安全。语义标签应为 overstated，范围错误，未处理继续监测这一限制。程序可能通过字节引用检查，不能据此标 supported。

可接受的参考表述：“在这份2010 Prius调查材料中，ODI基于Toyota采取的召回措施结案，并表示将继续监测；该材料不能推出所有混动车均已安全。”该表述限定到所引固定版本，仍不确认任一个体车辆。

练习二：构造“单条不足、两条联合足够”。

证据A：Products处的车型范围，字符区间 `[578,994)`；证据B：后部Summary，区间 `[2836,3446)`。后文的 subject vehicles 和制动条件需要前文的车型范围。仅A不能证明后文的措施/结案依据，仅B脱离前文不能完整解释 subject vehicles 的对象。A+B可以共同支持“该2010 Prius范围中的特定ABS问题及所述处理”；若同时谈Action字段，可补 `[2167,2234)` 或引用覆盖这些字段的完整页。字符位置是固定 layout 提取文本的Python字符索引，不是PDF坐标或网页位置。

练习三：计数为何不用检索？

参考答案：top 6只返回最相关的若干片段，重复块、多个部件标签和同一ODI都可能重复出现；它既不等于所有投诉，也不能支持全资料零。当前真实冻结资料中103个ODI、动力或制动86个、制动5个来自预定义 EXISTS 与 DISTINCT 查询。生产日期缺失时 confirmed count=0并伴随86个unknown，是部分可判定结果，不是“零相关投诉”。

练习四：如何判成功与失败？

参考答案：成功零记录返回 no_matching_records，范围限定在允许冻结资料；缺生产日期/配置返回 needs_clarification；请求无法由发布支持的历史时间返回 unsupported_time；没有投诉来源却要计数返回 insufficient_evidence。伪造引用、未知E999、截断或传输故障返回 execution_status=failed，保存工件且不显示生成答案。它们不会变成“无召回”。

## 可直接运行的验证

项目根目录，Python3.12及uv依赖已准备。合成测试和离线接口不需要模型凭证或官方原始资料：

```powershell
uv run --locked --offline python -m pytest -q tests/test_investigation.py --basetemp .local/iv-unit
uv run --locked --offline python -m scripts.verify_offline --output .local/P1-07/offline.json
uv run --locked --offline python -m scripts.verify_postgres --bin-dir .local/postgres/runtime/pgsql/bin --output .local/P1-07/postgres.json
```

官方资料验证需要现存的P1-06发布包，包缺失时按既有来源获取/解析/索引/发布流程准备，不能用占位资料冒充：

```powershell
# 冻结已看过开发资料的参考标签，零生成调用；不要覆盖已参与比较的标签版本。
uv run --locked --offline python -m scripts.prepare_investigation_cases
# 真实数据库/官方资料，回答由合成模型作证据不足示例，不是模型质量实验。
uv run --locked --offline python -m scripts.verify_postgres --bin-dir .local/postgres/runtime/pgsql/bin --investigation-checks --output .local/P1-07/dry.json
# 使用本机.env的DeepSeek凭证，至多4次真实调用，无自动重试，可能计费。
uv run --locked --offline python -m scripts.verify_postgres --bin-dir .local/postgres/runtime/pgsql/bin --investigation-checks --live-model --output .local/P1-07/live.json
# 有对应完整输入指纹的已保存响应时，可完全回放；缓存缺失则失败，不联网补齐。
uv run --locked --offline python -m scripts.verify_postgres --bin-dir .local/postgres/runtime/pgsql/bin --investigation-checks --replay-model --output .local/P1-07/replay.json
```

`uv --offline` 限制的是依赖管理器；显式 `--live-model` 仍会由项目程序联网。请据此区分依赖离线与实验联网。

已有开发数据库和已绑定任务时，`python -m investigation run REQUEST.json --output .local/result.json` 可单独执行。任务必须先经P1-06正式发布绑定；本模块不自动创建授权。API通过显式 `create_release_app(service=..., investigator=...)` 注入后提供 `/published/investigate`，验证脚本会演示并自动关闭。

盲审和评分使用保存的原始报告JSON（`.local/P1-07/reports/DEV-PRIUS-JOINT.json`），不是API附带路径的外层响应：

```powershell
uv run --locked --offline python -m investigation blind .local/P1-07/reports/DEV-PRIUS-JOINT.json --output .local/P1-07/review-export
uv run --locked --offline python -m investigation score .local/P1-07/reports/DEV-PRIUS-JOINT.json --reference evals/investigation-v0.2/DEV-PRIUS-JOINT.json --output .local/P1-07/unreviewed-score.json
```
