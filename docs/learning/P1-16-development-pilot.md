# P1-16续：建立当前系统开发基线前的预检

本轮仍在P1-16。目标是让后续独立评分有固定输入与明确义务，再据开发结果确定下一版测试质量目标。依赖固定资料发布、普通任务授权/Dispatcher/Worker、固定调查器、已有请求记账与独立审查工具；此前真实测试继续保留，不再用它调参或追认门槛。

## 本轮设计

`baselining/preparation.py`固定两组已见开发事件、8项任务及原始证据定位；同文的不同车型记录保留为替代，未根据系统matched结果删去参考证据。16项定义在3个回答任务中形成18个义务实例。定位证明出处存在，不能自动证明答案语义满足；标签来自实现代理，独立核对仍待进行。

新计划选择默认固定流程，使用原综合协议的当前配置和资料发布。它用于建立初步开发基线，不是四方法比较。2个已见事件簇、重复1次无法估计总体质量或给出可靠区间，后续开发与另一版未见测试目标仍保留。

`baselining/runner.py`复用普通`CellExecutor`，走真实来源/查询/检索/证据校验和共享预算。只在外围增加独立目录、数据库与新账本。`PreviewStop.generate()`先保存真实system/payload，再抛出明确的本地中止异常；没有假答案、usage或费用，不能把停止记录说成模型质量结果。

真实模式先核对新计划的实际用户批准，再初始化模型、账本和数据库。新账本将3项回答各限1次、其余5项限0；失败/未知占额、不自动重试。旧584次和P1-09批准不扩用，换输出目录也不重领额度。预检与真实目录分开，运行前登记全部8格，已领取格不自动重跑。

预检较慢的可观察事实是首个任务约数分钟后才抵达生成入口；它使用普通完整发布校验，不能称为模型响应耗时或据此推断模型很慢。具体耗时以本轮逐格原记录为准，未做性能优化或与历史方法速度比较。
