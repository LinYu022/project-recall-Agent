# P1-13：语义记忆与候选审核

本模块一次交付。目标是把已确认的偏好、项目约定和经过程序验证的操作规则保存成可审计、可撤销的长期记录，让后续调查按明确范围采用。依赖P1-10的上下文/工件和P1-11的持久执行；不改用记忆代替P1-06的官方证据。

## 必要原理

“用户希望中文回答”是偏好，可以确认并记住；“某车型一定安全”是官方事实主张，必须查业务证据；“可能是同一缺陷”是待检验假设。重复摘要只增加出现次数，不会自动改变来源或真实性。当前记忆候选支持这些类型的区分，但official_fact和hypothesis均不能晋升为确认记忆。

检索索引和缓存都是派生物。删除主记录后，即使某份缓存仍持有旧ID，也不能返回旧内容。项目、用户、数据版本、来源和有效期先决定能不能采用，相关度只在合格集合中排序。用户级偏好可供自己的多个项目使用；项目偏好只在该项目生效。同一kind/semantic_key在用户和项目范围都有值时，明确项目值优先，发生在排序/截断之前；同一作用域内更新需要显式替换审核。

审核是状态转移，不是一句“模型说已确认”。请求必须包含候选修订与内容哈希，服务端保存真实调用者和说明。更新也先生成候选；审核期间旧记录若已变化，旧审核不能覆盖新状态。删除/停用/过期/替换会清索引、推进代次并清缓存。

## 关键实现与取舍

1. `memory/contracts.py`定义声明、来源、候选审核、修改、作用域和领域指针。领域条目不能保存事实段落，只能保存固定操作规则或来源入口，规则必须来自安装表。
2. `memory/service.py`实现事务内审核、冲突、修改/删除、过期与检索。索引命中后仍核验主记录/审核来源；领域条目重新检查发布和规则指纹。当前采用可解释词项排序，没有宣称向量语义检索收益。
3. `memory/__main__.py`运行独立声明提取进程。有界JSON输入只生成待审候选；没有外部调用，因此候选与job可以在同一事务中提交，崩溃时一起回滚。不能将这个协议直接用于未来的网络模型提取。
4. `memory/runtime.py`把已选择的记忆作为单独memory_context注入。四种调查方法都可使用；记忆字符占用原输入预算，不生成E证据。每次生成输入前及发布前完整核验领域来源，每个日志步骤前后核验主记录未撤销。
5. `control/contracts.py`把记忆项目纳入计划与授权，默认关闭。执行中删除采用项会阻断发布；旧报告附加当前审计状态，新任务重新检索。恢复只有实际输入仍相同时才能重放旧响应。

安装规则的“验证”范围有限：确认生产日期/配置缺失时会触发现有前置条件，以及只有哈希而没有原文时校验拒绝。它们不是任意领域自然语言规则的语义证明。正文和来源文字始终不能改变权限、工具或结论约束。

## 三个练习与参考答案

### 1. 撤销错误偏好

范例：项目里保存“用英文回答”，后来发现应使用中文。先查询一次形成缓存，然后删除错误项。

参考答案：使用当前expected_revision删除；同一事务将记录置deleted、增加修订、删除活动索引、推进用户generation并清缓存。下一次查询和新任务不再出现它，不能只清某个Python变量。旧报告仍记录曾采用该项，但memory_audit显示当前deleted。新偏好必须新建声明/候选并审核；历史事实不能被改成“从未采用”。

成功验证：缓存命中后删除，数据库索引和缓存清空；即使注入旧引用缓存也无结果；第二个任务实际输入不含已删除ID。失败验证：删除后仍在生成中的旧快照不得发布，删除项不能通过disable或陈旧审核复活。对应删除/缓存、旧报告/新任务、生成期间撤销三个数据库检查。

### 2. 更新随数据版本失效的操作规则

范例：一条“缺少个车配置不确认适用性”的已验证规则绑定发布A与允许来源。任务改用发布B后，旧规则不应被自动搬过去。

参考答案：先验证A规则在B检索中不返回，再基于B的来源建立更新候选，重新运行安装规则及发布/来源检查；审核明确替换A版本。旧规则置superseded，新规则只在B和允许的来源/车型条件下生效。不能只修改缓存键或把release_id改成B后继续用旧审核。

成功验证：测试创建并发布两个真实本地fixture版本，B下旧规则为空，重新审核后返回B规则；旧记录保留审计。失败验证：不存在来源、错误记录版本、带事实文本的指针、已过期或规则实现指纹变化都不得继续采用。fixture来源与验证输入为合成，不冒称真实NHTSA版本更新实验。

### 3. 尝试跨用户或跨项目检索

范例：用户Lin和Other都拥有名称为recall的项目；Lin试图读取Other的记忆ID，并用高度相似的查询检索。

参考答案：每张主记录、候选、来源、提取job都绑定owner；身份由Bearer认证得出，不能在JSON里传owner_id。按owner/项目先筛选，再排序和limit。另一用户记录读取返回403；另一项目的项目记忆不进入候选集。同一用户的user范围偏好可以跨自己的项目，但项目级偏好不能据此变成全局偏好。

成功验证：相同项目名不会共享内容，少量limit不会被其他用户结果占位；伪造owner字段返回422且不回显敏感值。失败验证：不能先跨用户取top-k再过滤，也不能仅在API拦截而让后台worker按外部owner字段执行。

## 运行范例

先配置专用开发数据库，沿用既有认证服务设置。在项目根目录运行：

```powershell
uv run --locked --offline python -m alembic upgrade head
# 终端一：原认证API；默认8001。
uv run --locked --offline python -m control
# 终端二：独立声明提取worker，可常驻；--once只处理一个job。
uv run --locked --offline python -m memory --once
```

`RECALL_DATABASE_URL`与`RECALL_CONTROL_TOKEN_OWNERS`沿用P1-08～P1-11配置。下面只操作本地记忆API，不触发调查或模型；先在本机配置`RECALL_CONTROL_TOKEN`为已在映射中的一个用户令牌，不要把令牌发到聊天。

```powershell
$memoryHeaders = @{ Authorization = "Bearer $env:RECALL_CONTROL_TOKEN" }
$memoryApi = 'http://127.0.0.1:8001'
Invoke-RestMethod -Method Post -Uri "$memoryApi/memory/projects" -Headers $memoryHeaders -ContentType 'application/json' -Body '{"project_id":"recall","name":"召回学习项目"}'
$declarations = Get-Content -LiteralPath examples/memory-declarations.json -Raw -Encoding utf8
$sourceBody = @{project_id='recall'; origin='user_statement'; text=$declarations} | ConvertTo-Json
$source = Invoke-RestMethod -Method Post -Uri "$memoryApi/memory/sources" -Headers $memoryHeaders -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($sourceBody))
$enqueueBody = @{source_id=$source.source_id} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$memoryApi/memory/extractions" -Headers $memoryHeaders -ContentType 'application/json' -Body $enqueueBody
# 入队后再运行一次 python -m memory --once，随后读取候选。
Invoke-RestMethod -Uri "$memoryApi/memory/candidates" -Headers $memoryHeaders
```

示例内容带SYNTHETIC，供练习，不会自动写入真实个人偏好。审核时从接口取得候选的candidate_id/revision/proposal_sha256，POST `/memory/candidates/{id}/review`，传`expected_revision`、`proposal_sha256`、`decision=approve|reject`及note。冲突还需要replace_memory_id；更新走`/memory/items/{id}/edit`，重新审核后才生效。Swagger会展示严格Schema。项目已存在时创建返回409，可复用，不要重复覆盖。

正式调查若要采用记忆，在当前计划明确加入`"memory":{"project_id":"recall","enabled":true}`，沿用精确计划审批及任务worker。旧任务默认不采用记忆。真实worker可能调用用户配置的模型；本模块验收脚本显式使用模拟生成，没有新增provider请求。
