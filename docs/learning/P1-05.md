## 目标与架构位置

依赖 P1-03 的实体/条件判断与 P1-04 的可回放分块，本模块回答“从允许资料中，先读哪些证据块”。实现四种可切换方法、统一 CLI/API、范围通道、原文/关联展开、模型/索引记录、候选轨迹及开发实验。

检索负责候选和顺序，不代替总体投诉计数、不认定缺陷，也不证明个车适用。统计仍来自结构化全集；语义证据支持在 P1-07，正式版本发布在 P1-06。

## 必要原理与关键代码

BM25 根据词项匹配打分，对高词频做饱和并校正文档长度。实现采用：

```text
IDF = log(1 + (N - df + 0.5) / (df + 0.5))
score += IDF * tf * (k1 + 1) / (tf + k1 * (1 - b + b * length / average_length))
```

精确编号、车型和部件术语往往受益于稀疏检索。编号缩写只处理明确格式，不做近似编号替换。为保证重复执行，词项顺序和同分排序均固定。

dense 用真实 MiniLM 将查询和资料编码成向量，经 mask 均值池化和 L2 归一化，使用 Qdrant 余弦检索。它能比较措辞差异，但相似度不是事实概率；英语模型在中文查询上的效果没有验证。当前本地模式使用精确扫描，不宣称已经验证 ANN/HNSW 或远端服务器性能。

RRF 合并名次，而不把 BM25 和余弦分数直接相加：

```python
scores[identifier] = scores.get(identifier, 0) + 1 / (constant + position)
```

constant=60；每条方法先取前 30 个证据组。它降低不同分数尺度的影响，但不能保证每个问题都更好。

交叉编码重排把 query 和候选正文一起送入另一个真实模型，输出 logit。它只重排 hybrid 已找到的候选，未召回的证据不能凭重排产生；每次最多 30 项，因此额外成本可量化。

范围判断先于以上排序。已知冲突排除，必需元数据缺失进 pending。同一车辆位置须同时满足品牌/车型/年份，不能跨车辆字段拼接条件。API 按来源范围再次检查，展开也重新检查，不依赖模型自述。

官方 API 会按车型年重复同一段说明，所以先过滤再合并同一召回、字段、叶块和父文本完全相同的证据。每组只参与一次排序，但保留全部等价位置。这与把不同投诉或不同缺陷按相似语义合并不同。scope.py、ranking.py、service.py 分别负责这些判断，互不代替。

## 实际产物

- `retrieval/`：契约、语料构建、BM25/RRF、索引校验、Qdrant 与 NumPy 参考、ONNX 模型、统一服务、失败诊断及 CLI。
- `app/retrieval_api.py`：搜索和原文/显式关联展开；固定服务器索引、来源范围和模型，保留追踪。
- `examples/retrieval-*.json`：固定语料、实体/PDF 元数据、模型修订/哈希、配置与查询。
- `scripts/fetch_retrieval_models.py`、`restore_retrieval_sources.py`：可核验下载/重放。权重、原始投诉、Qdrant 数据库、完整结果与环境均留在忽略目录。
- `evals/retrieval/`、`scripts/evaluate_retrieval.py`：开发协议、相关性标签、四方法配对比较。
- `docs/architecture/retrieval-v0.1.md`、`docs/experiments/P1-05-retrieval.md`：契约、支持边界、结果及代价。

当前固定构建包含 225 条来源记录、593 个叶块、149 个去重证据组。向量为 384 维，模型文件固定修订和 SHA-256。编码上限 256 token，593 个输入中 28 个被截断；每次查询及重排也单独记录截断，原文/引用不被截短。

推荐技术栈的 Qdrant 已补齐本地持久化模式。加载时逐点核对数量、载荷与向量。真实两条向量查询分别检查 593 个点和 198 点子集，最大余弦差异小于 8e-8。NumPy 只保留为算法参考，不在缺 Qdrant 组件时替代生产路径。

## 完整运行范例

在项目根目录使用已锁定的 Python 环境：

```powershell
uv sync --locked
# 以下两条显式联网；已有资料/权重时校验后复用。
uv run --locked python -m scripts.restore_retrieval_sources
uv run --locked python -m scripts.fetch_retrieval_models
$build = uv run --locked --offline python -m retrieval build examples/retrieval-build.json | ConvertFrom-Json
$index = $build.index_artifact.sha256
```

参考答案：indexed、documents=593、384 维；dataset_build_id 为 `b84089a6465f68feab955ecaff920d444427c9f5b7a7c1e9a9e0bd37a0001980`，本机固定索引哈希为 `46373e84c19beb44a37ed3b2a2cf079d98b86ebf15f7a6cfbcc2b8852a616982`。相同固定原字节、环境、规则重复构建得到相同工件；不同平台数值/运行库变化可能产生新索引，不能自行替换旧标签绑定来宣称逐字节相同。

原文恢复只接受完全匹配的字节；资料已变时会明确失败，新下载清单单独保存，不篡改旧观察时间。完整干净环境验收仍在 P1-18，本轮没有伪称已在另一台机器克隆复现。

搜索并查看完整轨迹：

```powershell
$search = uv run --locked --offline python -m retrieval search examples/retrieval-query.json --index $index | ConvertFrom-Json
$tracePath = ".local/retrieval/traces/artifacts/$($search.trace_artifact.sha256).json"
$result = Get-Content $tracePath -Encoding utf8 | ConvertFrom-Json
$result.matched_hits | Select-Object rank, field, score, evidence_key
$result.candidate_trace
```

参考答案：返回同一构建、scope_channel=matched 的 Tesla 2022 Model Y 候选，并保留所选路径的实际阶段轨迹；默认 method=hybrid。分数仅可在相应阶段解释，不能把 BM25 分数与 logit 数值直接比较。

切换方法：复制该查询到一个新本地文件，改 method 为 bm25 / dense / hybrid / hybrid_rerank，再运行相同 search 命令。其他范围、语料、候选上限保持一致，不改开发标签去迎合结果。

回查第一项原文与父上下文：

```powershell
$document = $result.matched_hits[0].document_id
uv run --locked --offline python -m retrieval expand examples/retrieval-query.json --index $index --document-id $document
```

参考答案：expanded，保存独立展开工件，其中焦点、父块及必需上下文的每个来源范围均有精确引用。--include-related 只跟随已审查官方引用，且继续受来源与任务范围限制。

启动本地 API：

```powershell
$env:RECALL_RETRIEVAL_CONFIG = $build.server_config_path
uv run --locked --offline uvicorn app.retrieval_api:create_retrieval_app --factory --host 127.0.0.1 --port 8002
```

打开 `http://127.0.0.1:8002/docs`。POST `/retrieval/search` 使用示例查询；POST `/retrieval/expand` 接收 search、document_id 和 include_related。它会保存轨迹，不联网取数、不自动创建缺失模型或索引。使用完停止服务器；验证脚本启动的临时服务会自动关闭。

## 动手练习与参考答案

练习是根据候选轨迹诊断，而不是只看最终回答：

| 场景 | 如何检查 | 参考答案 |
| --- | --- | --- |
| 没有召回 | 先看索引是否含目标，再看范围通道及 BM25/dense 初始候选 | 无词项重叠的受控 BM25 查询为 not_retrieved；增加重排不能凭空找回 |
| 已召回但排名靠后 | 目标在候选中，检查最终位置和所用 k | 真实 Tesla Remedy 开发题的 BM25 目标在第 2 名；k=1 为 ranked_below_cutoff，不能误说索引里没有 |
| 条件过滤错误 | 对照请求范围、每个来源元数据和 scope_reasons | 把目标 2022 年写成 1999 年时会被排除；这是受控错误请求，不是过滤器故障。修正请求，不调高相似度绕过硬条件 |
| 条件未知 | 生产日期/配置缺失时看 pending_hits | 2016 F-150 投诉的生产日期未知，不能用车型年代替，也不能把 pending 塞回 matched |
| 编号、语义和质量混淆 | 对照精确编号查询与语义题指标 | 精确编号命中不表示风险解释或维修结论一定正确 |
| Qdrant/模型损坏 | 查看启动/查询失败与组件清单 | 哈希或逐点核对失败必须阻断，不自动换模型、回退 latest 或伪造零结果 |

已执行的诊断记录见 `docs/verification/2026-10-26-retrieval-diagnostics.json`，明确区分真实排序实例、无词项重叠/错误年份受控反例。真实模型还实际验证了过长 reranker query 在推理前被拒绝。

## 验证、结果与知识要点

真实模型比较、Qdrant 对账与本机 HTTP 验证单独记录；合成测试使用确定性假编码器/假重排隔离业务逻辑，不替代模型质量实验。新增 35 项测试，累计 255 项无数据库测试、49 个选定源码文件 mypy、Ruff 与迁移 SQL 生成通过。14 类真实检索 HTTP、旧两组各 7 类回环 HTTP 检查通过，临时服务均关闭。最终测量表和默认判断见实验文档与公开 JSON。

本模块没有新增数据库迁移，既有 38 项 PostgreSQL 测试未重跑。新增官方资料是开发集，非未见测试；没有生成式模型调用或调查 Agent 准确率结果。四个独立事件不足以支持普遍优势或中文效果声明，标签仍需正式评测前独立复核。

真实重排可以提高部分指标，但成本可能不符合默认策略；保留实现与开关，并按预先规定的开发门槛选择默认。BM25、dense、融合、重排各自的收益和失败位置都应能从轨迹解释，复杂性不是质量保证。

边界与修订记录：为避免 API 重复行膨胀排序/指标，采用过滤后的精确文本证据组；为避免把 Qdrant 推荐栈悄悄省掉，保留 NumPy 参考并补齐持久化后端，标签与数值参数不随结果改变。原计划副本保持不变，全部 P1-06～P1-18 目标保留。
