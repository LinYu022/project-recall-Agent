## 目标、依赖与原理

依赖 P1-02 的原始版本/映射，P1-03 的实体与条件，P1-04 的解析/引用，P1-05 的 BM25/向量/模型。本模块让它们成为一个完整、可核验的 DatasetRelease，防止调查中途读到不同批次的数据。

需要分清三种身份：dataset_build_id 固定语料；索引哈希固定检索组件；release_id 固定所有必需资料、规则、模型和环境。某个索引存在，不代表一份发布已经完整可用。

文件、Qdrant 和 PostgreSQL 没有共同事务。解决办法是先构建和验证完整组件，最后只在 PostgreSQL 事务中发布可见指针。失败候选保留为不可见产物；不能用“尽量写完了”代替发布完成。

任务必须在开始时绑定 release_id，而不是每次查询读取 default。否则，调查第一步可能读旧投诉，第二步却读新索引，同一报告难以复现。

## 关键实现与取舍

`releases/bundle.py` 保存独立发布副本及完整文件清单，按原始字节和包内规则重放语料；验证时使用独立 scratch，不修补或覆盖发布包。模型文件、tokenizer、规则和锁文件也纳入清单。Qdrant 采用逻辑点/载荷/向量核对，而非不稳定的 SQLite 文件字节哈希。

`releases/catalog.py` 管理数据库可见性、任务、报告引用和回收。默认切换采用比较并交换：

```python
if current != request.expected_default:
    raise ReleaseConflict("default changed; compare-and-swap rejected")
```

发布行、成员、默认指针和审计在同一事务里。两个发布者基于同一个旧默认值操作时，只有先提交者成功；另一个明确得到冲突，不能覆盖前者。

`releases/service.py` 从数据库任务绑定取得固定版本，再核对所有存储。单次查询不允许传入新路径、范围或来源来扩大任务。搜索、原文、计数、关联使用同一发布；总体计数仍来自结构化全集，不能由检索前几项代替。

回收使用 available → retiring → collected。先检查任务/报告/期限，再禁止新绑定，之后删除独立副本。失败时保持 retiring，可重试；不会删除共享来源行、全局原始文件或其他发布。

当前取舍是每次正式查询完整校验，优先保证来源可回放和故障可发现，开销高于纯检索。响应 `published_elapsed_ms` 包含验证/加载，`total_ms` 仅是检索阶段，不能混为一个指标。当前 Qdrant 本地模式单进程使用，未声称远端服务或多 worker 吞吐验收。

## 完整运行范例

准备已有资料和模型后，可重建两个候选：

```powershell
uv run --locked --offline python -m scripts.prepare_release_candidates
$candidates = Get-Content .local/release-candidates.json -Encoding utf8 | ConvertFrom-Json
uv run --locked --offline python -m releases verify $candidates.candidates.baseline.manifest_sha256
```

参考答案：sealed/verified；只有候选清单，数据库 default 尚未改变。来源、模型、Python 或锁文件变化会产生新构建或明确拒绝复用，不能直接套旧请求文件里的身份。

使用自备开发 PostgreSQL 时，先设置 RECALL_DATABASE_URL，再迁移与发布：

```powershell
uv run --locked --offline python -m alembic upgrade head
uv run --locked --offline python -m releases publish examples/release-publish-baseline.json
uv run --locked --offline python -m releases bind examples/release-bind-task.json
uv run --locked --offline python -m releases query examples/release-query.json
uv run --locked --offline python -m releases publish examples/release-publish-expanded.json
uv run --locked --offline python -m releases query examples/release-query.json
```

参考答案：第一次发布要求 default=null；两次 query 都返回基线 release_id，即使第二次执行时 default 已是扩展版。复用相同任务绑定不会重新选默认值。示例发布请求绑定本批清单；若已有默认值或构建不同，应另存请求并填入实际 expected_default，不能把冲突当成功。

回滚：

```powershell
uv run --locked --offline python -m releases rollback examples/release-rollback.json
uv run --locked --offline python -m releases list
```

参考答案：默认指针回到基线，扩展版保留，已有任务不换版本。回滚也验证完整性和 expected_default，不是重写旧目录。

正式 API：

```powershell
uv run --locked --offline uvicorn app.release_api:create_release_app --factory --host 127.0.0.1 --port 8003
```

打开 `http://127.0.0.1:8003/docs`。先 POST `/tasks/bind`，再 POST `/published/search`。未绑定任务/混用 release_id 返回 409，试图在查询里覆盖 scope 返回 422，来源越界返回 403，缺本地组件或数据库不可用返回 503。运行完停止服务。本模块的自动验收使用临时数据库/schema，不会替你留下一个常驻部署或永久默认发布。

## 练习与参考答案

| 场景 | 参考答案 |
| --- | --- |
| 任务执行中发布新数据 | 旧任务保留旧 release_id；新任务才读取新默认值。更换范围或版本需新任务，不能改旧绑定 |
| 候选向量组件未完成 | 发布被阻断，默认值保持原版本；不退回 NumPy 或 latest |
| 文件内容改了，又更新清单中一项哈希 | 仍须通过清单身份、角色完整性、原字节重放、模型身份和数据构建交叉核对；不能只验证单文件 |
| 数据库 model_year 改了，索引没改 | 正式查询被拒绝，不把两个存储中的值拼在一起 |
| 指针更新后注入故障 | 数据库事务回滚目录/成员/默认值/事件；已准备文件或追加版本可保留但不可见 |
| 两个发布者都期望同一个旧默认值 | 一个成功，另一个得到 CAS 冲突，重新检查当前默认再决定 |
| 旧包非默认，但有活跃任务 | 回收计划返回 active_tasks，不能删 |
| 任务已结束，但报告持续引用 | report_references 继续阻止回收；不能为了释放空间丢掉报告出处 |
| 期限/引用都满足，删除中断 | 保持 retiring，禁止新绑定；重试继续清理，最后 collected |

可以只检查回收资格：

```powershell
uv run --locked --offline python -m releases collect $candidates.candidates.baseline.release_id
```

参考答案：当前真实包因默认值、活跃任务、引用或保留期限而 retained，不会删除。--execute 只对完全 eligible 的独立发布包执行回收；共享数据仍保留。完整删除边界和恢复已在合成数据/测试时钟上实际执行，不建议为练习修改真实保留政策。

复现自动完整验收：

```powershell
uv run --locked --offline python -m scripts.verify_postgres --bin-dir .local/postgres/runtime/pgsql/bin --release-checks --output .local/my-release-checks.json
uv run --locked --offline python -m scripts.verify_offline
```

其他机器自备 PostgreSQL 二进制，先按 P1-05 恢复相同字节并准备候选。脚本使用临时密码、独立 schema 与自动启停，不把本地等价 CI 说成远端 GitHub Actions 运行。完整干净环境复现仍在 P1-18。
