# P1-12：按需多Agent与矛盾证据聚合

本模块一次交付。目标是让两个调查器在同一父授权和总额度下独立推进，并让主调查器对分歧查原文、保留未知。依赖P1-09的有界调查循环、P1-10的上下文/工件、P1-11的持久队列/根预算。它位于调查执行层，向后为P1-16的四方法比较提供可运行机制；不会替代数据发布或语义审查。

## 必要原理与代码阅读顺序

并发解决等待，独立上下文解决职责和信息组织，两者不同。单Agent可以同时发search和links，却仍只有一个规划者；多Agent的两个规划者各自看到目标、证据和工具观察，最后主调查器另建输入。更多Agent也可能带来重复、冲突和更高的上下文开销。

先读`investigation/collaboration_contracts.py`。Delegation不是一句“请查资料”，而是父权限的收窄描述：版本、范围、输入、工具和资源都要具体。再读`cooperation.py::trigger/allocations`，理解为什么简单任务退回单Agent、为什么分配3+4+1次生成而非每人8次。业务条件决定工具是否存在，角色白名单只是再收窄一层。

然后读`agent.py::run_batch`与`cooperation.py::run_branch`。前者保留一个规划上下文，要求两项工具没有数据依赖；后者为数据/文档建立独立循环，并只共享lookup卡与原始工件。两个分支的E001可能对应不同对象，主调查器必须按完整证据ID重新映射。

最后读`cooperation.py::conflicts`、主调查器`verify_cards`与`control/journal.py::fork`。先回放证据，再把分支语义摘要交给汇总模型；模型说得肯定不代表原文真的支持。局部额度与根池都受持久账本限制，重启不能获得额外资源。

关键取舍：当前为两种专门角色、确定性静态份额，没有动态招募或互相聊天。输入额度优先分给文档分支，保留一份汇总额度；兄弟空闲额度不自动借用。真实资料演示出现局部输入耗尽，会如实交付不足。Qdrant local的同目录访问需要排队，模型/其他工作可以并行；机制成立不等于已经测出速度提升。

## 三个练习范例与参考答案

### 1. 对同一召回得出相反适用性判断

范例：DATA提出TASK适用性supported，引结构化车型记录；DOCUMENT提出contradicted，引含配置条件的文字。这里的相反判断是受控模拟，不能当成真实召回结论。

参考答案：先检查两个判断的issue和subject是否真在讨论同一对象，再核验双方原文、车型/年份、生产日期、配置和否定条件。重复支持意见不能增加证据份数。当前实现保留双方证据和`unresolved_after_source_replay`，最终`insufficient_evidence`，将`individual_vehicle`保留为待核实项。不能让两票支持压过一条明确条件。

验证成功：冲突表有双方来源，原文回放次数可查，最终写明未确认。验证失败：只引一方、丢否定条件、计票确认个车，或把引用哈希通过当语义正确。对应`test_opposing_applicability_proposals_preserve_both_sides_without_voting`。

### 2. 一方超时、一方成功

范例：模拟DATA生成阻塞超过分支期限；DOCUMENT完成检索/展开。

参考答案：保存文档分支证据，数据分支标timeout，主调查器说明缺失并交付不足。在途调用预留保持unknown，不能当成零费用或再生成一次。迟到返回可留档及结算，不得回写已发布结果。父任务取消则两个分支都失去正式发布权限。

验证成功：文档分支确实在数据阻塞时推进，最终同时记录completed和timeout；未知响应保留预留。验证失败：整个报告抹掉成功分支、超时解释成没有召回、迟到响应覆盖结果。对应`test_document_branch_progresses_while_data_branch_is_blocked_then_timeout_keeps_success`和`test_uncertain_branch_model_call_does_not_pause_successful_sibling_or_release_budget`。

### 3. 重复调查与恢复

范例：两分支都需要相同结构化lookup，随后worker在汇总响应保存后退出。

参考答案：父流程只做一次lookup，双方引用同一证据身份；聚合按身份去重，不按引用次数计票。恢复时新epoch重新校验授权和冻结发布，重放分支/汇总已完成响应及工具结果，仍做原文完整性审计。不得因为run_id或计时变了再次请求模型，也不得为unknown响应自动重发。改变来源、授权或实际输入则停止。

验证成功：账本lookup一次，双方种子证据ID相同，最终证据ID不重复；恢复新增模型调用0，旧响应重放数与已保存数一致。验证失败：共享整段聊天造成隐形串行化、每个分支独占全额预算、恢复再次收费，或忽略真正输入变化。对应隔离/共享额度、multi恢复、parallel恢复及lane额度检查。
