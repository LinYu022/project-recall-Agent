# P1-10：上下文构建、结构化摘要与原文回查

本模块依赖 P1-09。目标是让模型在有限输入中看到当前目标、授权限制、计划、关键证据、反证和最近动作，并能从工件分页及精确引用回查原文。它位于工具输出与下一轮决策之间，直接处理上模块 Prius 展开后输入超限的问题。

## 必要原理

完整留档与全部塞入提示词是两件事。完整结果应留在不可变工件中，每一轮只选择相关内容；被省略的资料必须还能找到，不能被解释为“没有记录”。单纯最近窗口会忘掉早期反证，而重复拼接父段、原文和旧决策又会挤占预算。

压缩有损失。本实现先做可核验的结构化抽取与精确重复合并：保留完整证据块及来源版本，条件/否定/未确认项、反证和父段依赖优先。它没有让另一模型改写事实；摘要模型调用数为0，provider用量/费用为null。本地构建耗时另记。提示缓存即使存在，也不能让超额输入变小或替代信息选择。

## 实现与关键设计

`investigation/prompt_context.py`提供ContextBinding、StructuredSummary、构建器、已登记工件及分页。完整快照和摘要先落盘，恢复时用可信运行记录中的预期快照哈希和当前修订/授权/执行代次校验，再重建摘要比较内容。改了文字却重新计算摘要哈希，也不能骗过原始快照比较。

证据按完整投影、精确定位和来源版本去重，保存全部等价别名。必要内容和传递依赖闭包固定保留，其余按问题相关度和最近获得顺序加入。词项保护是针对当前资料的保守规则，不保证识别任何语言的所有语义条件；完整留档、省略标记、回查和独立语义审查仍有必要。必要集合本身过大则停止，不能删反证换取继续执行。

`investigation/agent.py`在每轮生成前调用构建器，记录上下文前后大小与耗时。`read`决策通过A工件或E证据别名分页读取，占用原工具额度。完整展示过或完整读完的证据才能用于最终引用；片段、D候选及模型自己的摘要不能直接充当新来源。

`investigation/inspection.py`和受保护`/tasks/{task_id}/context`提供报告日志、工件分页与证据原文回查，继承用户所有权和当前授权检查。来源字节、解析配方与精确位置都要重放；接口不接受任意本机路径。

新服务/直接SingleAgent使用structured；历史显式FixedConfig缺字段时仍是full_history，原固定流程默认不变。最近窗口仅用于消融。计划和授权不能因上下文压缩而扩大；后台任务恢复继续属于P1-11。

## 动手练习与参考答案

练习：将“2010 Prius相关调查结案不证明所有车辆均安全，个车适用性未知”的重要反证放在长轨迹前段；追加大量无关观察，比较完整历史、最近窗口和结构化摘要。

范例由`scripts.verify_context`构造，明确标记SYNTHETIC。20次决策及8张证据卡中，早期反证含`does NOT establish universal safety`，父段含车型/年份，旧缺口含`individual_vehicle`。它们是受控练习，不能冒充NHTSA的真实原文或模型评价。

参考答案：完整历史保留反证但超预算；最近窗口能变小却可能丢反证；结构化摘要应固定保留反证、车型/年份、父段和未核实项，只将其余完整块按预算选择。不能把“不再出现在最近决策中的缺口”当成已核实解决。若必要内容仍超限，应返回不足并保留工件，而不是静默截断。

```powershell
# 可在本仓库干净依赖环境中运行；不需要密钥、数据库或真实资料缓存。
uv run --locked --offline python -m scripts.verify_context
uv run --locked --offline python -m pytest -q tests/test_prompt_context.py --basetemp .local/ctx-exercise
```

成功场景：structured仍包含完整反证及父段，current_hypotheses保留contradicted，unresolved_conditions保留individual_vehicle，字符数在24,000以内。此处比较的是信息保留与预算，不是模型回答正确率。

失败场景及参考答案：删除摘要中的NOT并重新保存哈希、改source_version_ids、删除输入快照，恢复均应拒绝；更换revision_id、authorization_id、epoch或release_id也拒绝。分页使用未知A句柄、路径、负偏移或大于4000的页长应失败。原文解析工件改动即使只是追加空白，字节哈希核验也应失败。数据库测试会临时注入该错误后恢复测试文件，不触碰真实冻结包。

```powershell
# 已有专用测试数据库及RECALL_TEST_DATABASE_URL时：
uv run --locked --offline python -m pytest -q -m postgres tests/test_prompt_context_postgres.py --basetemp .local/ctx-db-exercise
```

原文分页不能单独证明结论。读完一张证据还需读其required_context，最终继续由Claim验证和独立语义审查负责。过期摘要也不能通过“重新装载”自动恢复旧授权。

## 真实资料检查与复现

本机已有P1-09固定发布与私有原报告时：

```powershell
uv run --locked --offline python -m scripts.verify_context --official
uv run --locked --offline python -m scripts.verify_offline --output .local/P1-10/offline-final.json
uv run --locked --offline python -m scripts.verify_postgres --bin-dir .local/postgres/runtime/pgsql/bin --output .local/P1-10/postgres-current.json
```

Prius的24张真实证据卡按相同来源版本和完整定位合并为8组；重建的下一轮输入由28,522字符降到19,693字符，全部8组保留，含车型/年份与继续监测条件。已回查全部24张卡。这是从保存状态重建的未发送输入，没有调用模型、没有证明最终回答改善，也没有把P1-09的失败改写为成功。

本机回放P1-09的8份旧响应也通过：仍重现两个固定回答、Prius不足及车门失败，0新增请求。正式独立人工审查仍0份，语义指标null。公开摘要和Schema可提交Git；`.local`的原始资料、响应和数据库不提交。没有本地缓存的机器运行合成练习；完整干净环境资料复现与GitHub交付仍按P1-18完成。
