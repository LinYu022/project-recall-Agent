## 目标、依赖与作用

本模块把模糊业务请求转成能验收的任务：研究什么、能用哪些来源、什么输出算合格、哪些推断不允许、缺信息怎么办。

前置依赖：无工程模块。只需理解 JSON 的对象、数组、字符串与 null；暂不需要模型、数据库或编排框架。它为后续数据字段、检索标签、Agent 停止条件和公平评测提供共同依据。

完整模块仍需：约 10 个真实探索任务，覆盖直接查询、跨源关联、证据不足、条件歧义和反例；任务 Schema、标注规范、评分草案和事件簇划分规则。本轮没有将一条示例冒充模块完成。

## 三个必要原理

1. 正确性与完整性分别评价：一句话可能有证据，但遗漏限制条件或反证后，整份回答仍不合格。
2. 事件时间与知识时间不同：事件何时发生，与某个内容版本何时能被知道，是两个问题。现在查到旧召回不等于还原当时已公开的同一内容版本。
3. 未知也是可验证结果：车型范围匹配只支持相应层级的关联；缺少个车条件或投诉证据时，保持未知比补猜结论更符合任务契约。

## 第一步：任务卡 + 一次手工跟踪

产物：`evals/exploration/tasks/EXP-001.json`，字段解释见 `evals/task-contract-v0.1.md`。

把“查一下 Prius 刹车召回”收敛成：核对美国、TOYOTA、PRIUS、2010 车型年、10V039000 的官方记录，并说明可以和不可以据此断言的内容。

关键字段与取舍：

- `scope` 把品牌、车型和车型年写明，避免把相邻记录或其他车型混入结果。
- `required_outputs` 与 `forbidden_inferences` 同时定义“要回答什么”和“不能推出什么”，不能仅按关键词或是否有引用评分。
- `release_id: null` 表示尚未绑定冻结数据，`status: draft` 阻止把探索材料误称为正式评测。真正的运行阻断机制尚未实现。
- 本题按召回编号查询，不筛投诉事件，所以事件区间明确为 null。正式投诉任务会要求事件区间；不能用车型年代替事件时间。

真实手工数据流：

`任务范围 → 官方召回 API → 两条车型记录 → 按品牌/车型/车型年取匹配记录 → 按召回编号识别同一事件 → 写有限结论与未知项`

人工核查结果：官方展示两条记录，均属于 10V039000，只有其中 TOYOTA / PRIUS / 2010 记录匹配本题车型范围。制动描述涉及粗糙或易滑路面、缓慢持续制动及 ABS 介入后的制动感觉与停车距离。该记录不能独立证明任意个车适用，也未核实某条投诉的因果。

来源：[官方召回 API](https://api.nhtsa.gov/recalls/campaignNumber?campaignNumber=10V039000)、[车型与个车查询边界](https://www.nhtsa.gov/recalls)。具体字段与读取限制见 `docs/data/source-register.md`。

## 成功与失败的验证

| 检查 | 本步实际结果 | 证据类型 |
| --- | --- | --- |
| 官方来源能否读到记录 | 网页工具读取成功，展示 Count=2 | 真实在线人工核查 |
| 两条记录是否为两次召回 | 编号相同，按编号去重为 1 个召回事件 | 真实字段人工对照 |
| TOYOTA / PRIUS / 2010 是否有匹配记录 | 有；LEXUS / HS 记录不属于本题车型范围 | 真实字段人工对照 |
| 是否已取得原始快照 | 没有；直接网络获取失败，未保存 HTTP 原始响应 | 真实失败与限制记录 |
| “Count=2 所以两次召回”是否合格 | 不合格，统计单位错误 | 基于真实字段的受控错误示例 |
| “同年同车型所以我的车一定适用”是否合格 | 不合格，缺少个车适用范围证明 | 受控错误示例；未运行 Agent |

这些结果不是检索评测、模型质量实验或自动化验收结果。

## 首次练习参考答案

1. 10V039000 涉及部分 2010 车型年 Toyota Prius；官方描述粗糙或易滑路面上缓慢持续制动、ABS 介入后的制动感觉不一致等现象。保留这些条件。
2. 缺少个车生产、配置及范围证明时，不能确认任意车辆适用；缺少具体投诉原文与关联证据时，也不能确认投诉原因。
3. 两条车型记录分别对应 Toyota 与 Lexus，共用 10V039000 编号。车型记录数为 2，按召回编号去重为 1 个事件。
4. 调查结束但证据不足，表示流程可以结束而结论仍有未知项；来源访问失败表示资料没有取得，不能据此推出没有召回或缺陷。

“所有 2010 Prius 的刹车投诉都由这次召回解释”扩大了车辆范围、抹去症状条件并作出未经验证的逐条因果推断。

原计划三类说明范例：

- 有投诉但未确认缺陷：ODI 11766023 提及 20S31，只能先记录投诉自述；官方范围与个车故障仍需独立核对（EXP-004）。
- 相似召回但范围不符：20V469 与 23V162 均涉及前制动软管，但 Edge/MKX 与 Fusion/MKZ 范围不同（EXP-010）。
- 需要补充条件：14V284 除车型年外还有生产日期限制，仅有“2008 Escape”不足以确认个车适用（EXP-003）。
