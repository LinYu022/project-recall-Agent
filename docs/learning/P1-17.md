# P1-17：交互产品与端到端验收

2026-10-29。根据学习者“每模块完整交付一次、练习直接给参考答案”的要求完成本模块整合，不再逐段等待代码确认。

## 目标、依赖和位置

本模块把已经存在的调查、授权、固定发布、任务恢复及三类记忆接到可操作的 React 界面。前置依赖是 P1-06 的不可变数据发布、P1-07 的 Claim/Evidence、P1-08 的计划与权限、P1-11 的持久化执行，以及 P1-13～15 的可撤销记忆。P1-16 提供真实结果和已知质量缺口；界面必须诚实呈现这些边界。下一模块 P1-18 才负责第三方完整复现、公开仓库、tag 和 Release。

学习目标是理解：一份界面为什么必须同时处理任务状态、数据版本和证据质量；按钮与后端事务如何共同阻止旧授权、旧页面和越界数据；如何把一次浏览器操作追到原始资料与执行工件。

## 关键代码与取舍

- `portal/api.py` 复用原有控制 API，并提供经同一授权检查的历史、记忆和原文读取视图。原文必须先找到已发布报告中的别名，不能把任意文件名传给服务端。
- `frontend/src/main.jsx` 使用 React 状态展示服务端返回值。`expected_version` 防止旧页面覆盖新状态；批准绑定具体修订和 hash。`refresh` 不把 `COMPLETED` 翻译成语义通过。
- `EvidenceBody` 先展示原文，再提供完整定位元数据；哈希保证引用没有被换掉，不保证引用支持结论。支持、反证和必需上下文不能相互替代。
- `portal/__main__.py` 建立实际 PostgreSQL 服务连接、发布和 Worker。执行先持久化入队，页面每两秒轮询可观察状态，不伪造进度。
- `portal/demo.py` 的样例与模拟适配器独立且显式标注；它固定弃答，并可用显式标记产生本机故障。真实工具和浏览器成功不能拿来补模型质量分数。
- `portal/identity.py` 给产品代码及前端构建单独留指纹。原 P1-16 生成冻结继续原样校验，产品测试不追认旧实验质量。
- 两套锁文件分别约束 Python 和 Node 依赖。容器配置是复现入口的一部分，但写好文件不能替代实际启动验证。

取消与暂停是不同意图：暂停后继续使用当前计划，取消后创建新任务。撤销记忆会让后续采用失效，但不会改写旧报告和旧人工评价。

## 练习范例与参考答案

**练习一：运行完成是否等于回答成立？** 使用模拟模式创建 Prius 调查，提出执行版本、批准、执行。

参考答案：任务可以 `COMPLETED`，答案处置仍是 `insufficient_evidence`，独立语义核查仍待审。正确界面同时显示这些信息，不把空结论包装为成功答案。查看任一文本卡，原文回放验证通过也只说明字节、解析与区间一致。

**练习二：成功与失败如何验证？** 用“缺少年份”先创建任务，再填写 2010；另用“年份不匹配”查 2011 年款；再运行“模拟请求失败”。

参考答案：第一项等待输入且不猜年份，补充后计划可继续。第二项仅报告所选冻结来源内无匹配，不证明全球无召回。第三项是明确的本机传输故障注入，持久化层按“输出未知”将任务暂停且不发布报告，需要核对而不自动重发；没有真实网络调用，不能称为外部服务真实故障或模型语义失败率。

**练习三：关系与反证。** F-150 模式选两条原始记录并固定关系，读取已选关系和所有条件。

参考答案：同车型、同部件或范围重叠只支持有限的关联。必须保留两份缺陷描述的配置、触发条件、生产区间未知项；不能推出同一缺陷或具体个车适用。年份不匹配证据也可反驳跨年份外推，但不代表不存在其他来源。

**练习四：旧页面与错误记忆。** 两个页面打开同一任务，在一个页面暂停，再在旧页面操作；准备一条演示偏好候选，检查后确认并停用。

参考答案：旧版本操作被服务器拒绝，需要刷新后重新检查，不能自动批准。记忆状态变为 disabled 并保留来源和历史；这是一条用户偏好的撤销演示，不能把候选反复出现当作事实确认。
