# P1-15：程序性记忆与可验证 Skill

本模块一次交付，目标是把重复、可回放的调查过程变为有前置/后置条件的候选配方，在来源之外的任务与事件验证后才允许启用。依赖P1-13的记忆隔离/撤销、P1-14的经历/出处，并复用P1-08～P1-11的授权、工件、预算和恢复。完成后停在本模块，等你确认理解再进入P1-16。

## 必要原理与代码

经验文字只能提示“可以这样查”；可执行Skill还要回答：参数从哪里来、何时适用、允许做什么、怎样判定完成、失败如何处理、何时失效。一次成功可能来自巧合，同一事件的多个任务也不是多个独立经验。版本与回滚保留的是经过验证的定义和出处，不是把一段旧回答复制到新问题。

按以下顺序阅读即可追到完整链路：

1. `memory/procedure_contracts.py`：Procedure包含参数、前置条件、允许工具/动作、后置条件、到期时间与失败策略。Schema可以保存不完整candidate用于练习，compile_procedure始终保留生产硬约束。
2. `memory/procedure_engine.py`：参数只取当前任务，执行lookup/search/expand、构造当前E卡并verify_cards。scope_inspected不是最终答案；个车适用与因果始终未确认。
3. `memory/procedures.py`：从多个已核验episode提取候选、按事件族去重、执行未见目标、保存证明及管理版本。验证未调用生成模型，幂等请求不重复消耗工具。
4. `memory/procedure_runtime.py`：把已启用版本作为可撤销计划建议，记录采用和应用。`investigation/agent.py`中的apply_skill仍逐次调用现有工具和Journal，不另开权限或预算。
5. `app/procedure_api.py`、0009迁移及`control/service.py`：认证接口、四张表、当前授权与发布核验；读取旧报告附当前Skill审计。

安装一个有界配方比执行任意流程代码更容易核验。当前配方检查召回范围：make/model/year必需，applicability还要生产日期和配置；lookup→search→expand后重放原文、保留条件和未知。它不能确认某辆车适用，也不能把旧任务成功状态当成当前业务证据。

## 练习一：写出范围检查流程并迁移

范例：从Prius 10V039000与Ford 17V331000两个事件的已完成范围检查中提取candidate，再在Tesla 23V838000上做迁移。这里使用既有官方冻结资料，不从网络临时换数据。

参考定义的核心结构：

```python
definition = Procedure(
    release_ids=[current_release_id],
    expires_at=database_time + timedelta(days=7),
)
# 默认参数：task_scope/task_query/task_release/task_sources
# 默认动作：lookup → search → expand
# 默认后置：重放来源、保留范围上下文、个车适用仍未知
```

参考答案：先以两个不同事件的episode建立candidate；目标任务必须是同项目DRAFT/PLAN research，不能与来源任务或来源事件重叠。验证实际调用3次工具并回查证据，才将candidate变为validated；启用时还要固定当前版本和head revision。使用者当前任务仍须独立授权、参数完整、来源允许。

成功场景：未见事件的lookup/search/expand真实执行，验证新增模型调用为0，生成的E卡绑定目标任务。失败场景：只有一次来源、同事件重复来源、目标事件重叠、多个目标实为同一事件，都不能晋升。工程fixture的未知召回编号是明确合成数据，官方演示另行记录。

“未见”是相对于这个Skill的来源经历；官方包仍是已有开发资料，不当作P1-16正式未见测试集。

对应测试：single_success、real_transfer、duplicate_origin_event、multiple_targets。官方演示的最终回答为不足，不能称为“成功确认召回适用”。

## 练习二：删除前置条件，观察误触发再停用

范例：当前任务知道make/model但不知道year。把candidate.required_fields里的model_year删除。

```python
unsafe = definition.model_copy(update={"required_fields": ["make", "model"]})
missing_preconditions(unsafe, scope_without_year, request, current_release_id)
# 单看这个被删改的选择谓词，可能错误地返回 []。
compile_procedure(unsafe)
# 必须报 procedure_missing_or_changed_mandatory_guards。
```

参考答案：上面的空缺列表是谓词变异模拟，说明如果完全相信可编辑前置条件会误触发；不是实际执行了不安全流程。生产编译器拒绝缺强制条件的候选，工具调用应为0。原有安全版本遇到未知year也必须阻断，即使按campaign编号可执行普通查询，也不能绕过Skill自己的前置条件。

停用可用deprecate；有缺陷版本可revoke，后者不可复活。需要退回旧实现时显式rollback到仍有效的deprecated版本，重新核验出处、迁移证明、到期时间及当前代码。版本已过期、源episode停用、迁移目标撤销或证明工件缺失都不能继续执行/发布。

中止running验证后，已在途的只读查询可以结束，但不得因迟到结果变为validated；意外中断保留running，重复请求只返回原记录，需显式abort关闭。不把“未记录完成”假定为“从未发出”。相关测试包含中止、未知中断、失效传播、版本切换和已完成步骤恢复。

## 练习三：与普通文字经验比较

范例：同一特斯拉范围/来源/检索配置和调用上限。普通Plan.steps写“lookup后search、expand、重放并保留未知”；Skill版本显式选择已启用流程。

参考答案：脚本普通Agent依次search、expand、finish，3次模拟生成；Skill脚本apply_skill、finish，2次模拟生成。二者实际工具均为lookup/search/expand共3次。组合动作减少的是这份脚本的决策步数，工具并未消失；额外定义/验证检查可能增加输入和本地开销。

不能从这组演示推出真实模型质量/费用/延迟收益。应保留同任务、同来源、同上限，区分真实provider tokens与脚本usage，并在P1-16做独立评价与公平对照。这里没有给你未提交的答案评分。

## 复现

```powershell
uv run --locked --offline pytest -q tests/test_procedures.py
uv run --locked --offline python -m scripts.verify_postgres --bin-dir .local/postgres/runtime/pgsql/bin --test-filter procedures --procedure-checks --output .local/P1-15/exercises.json
uv run --locked --offline python -m scripts.verify_offline --output .local/P1-15/offline-final.json
uv run --locked --offline python -m scripts.verify_postgres --bin-dir .local/postgres/runtime/pgsql/bin --procedure-checks --agent-checks --replay-model --agent-profile-record .local/P1-09/live-final.json --agent-model-call-cap 4 --output .local/P1-15/final.json
uv run --locked --offline python -m scripts.export_procedure_verification
```

第一条用合成契约，不需数据库。第二条包含真实临时PostgreSQL及官方资料演示，需已有冻结包、权重；最后的旧响应回放还需P1-09记录。缺输入时明确失败，不自动下载或调用模型。只做数据库fixture检查可去掉procedure-checks；新机器应保留自己的验证记录。

认证API沿用P1-13配置，升级`alembic upgrade head`后由`python -m control`启动，任务worker单独运行。候选/验证/状态/回滚接口及字段见[架构](../architecture/procedural-memory-v0.1.md)；每一步使用服务返回的真实ID和修订，不复制临时演示ID。

以下是已有授权开发库中的调用顺序范例；变量需来自该库自己的项目、episode与DRAFT/PLAN目标，不是另建虚构来源。省略definition时默认绑定来源release，跨release需显式提交完整定义。

```powershell
$procedureHeaders = @{ Authorization = "Bearer $env:RECALL_CONTROL_TOKEN" }
$procedureApi = 'http://127.0.0.1:8001'
$candidateBody = @{project_id=$projectId; skill_key='inspect-scope'; origin_episode_ids=@($episodeA, $episodeB)}
$version = Invoke-RestMethod "$procedureApi/procedures/candidates" -Method Post -Headers $procedureHeaders -ContentType 'application/json' -Body ($candidateBody | ConvertTo-Json -Depth 12)
$validationBody = @{expected_revision=$version.revision; definition_sha256=$version.definition_sha256; target_task_ids=@($targetTaskId); idempotency_key='scope-check-001'}
$check = Invoke-RestMethod "$procedureApi/procedures/$($version.version_id)/validate" -Method Post -Headers $procedureHeaders -ContentType 'application/json' -Body ($validationBody | ConvertTo-Json -Depth 12)
# check.state 必须为 passed；再GET版本取得新revision/head.revision，POST /state启用。
# {expected_revision, expected_head_revision, action:'enable', note:'本次验证依据'}
# 后续任务Plan.skill显式选该version_id；原任务授权/来源/预算仍独立生效。
```

验证失败要读证明failure_code；不要更换幂等键反复盲试。中断且状态running时用GET /procedure-validations/{id}核对，再按实际情况显式POST /abort并记录原因，不能把重复请求当自动恢复。

产物、实际计数、失败轮次和真实/模拟边界见[实验记录](../experiments/P1-15-procedures.md)及[机器摘要](../verification/2026-10-28-P1-15-procedures.json)。本轮不新增模型或来源请求，P1-09许可不扩用；P1-16～P1-18及最终GitHub目标完整保留。
