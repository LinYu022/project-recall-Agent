# 项目一：公共产品质量与召回证据调查 Agent 实现计划

版本：v2.0  
修订日期：2026-10-26  
最终交付：能够独立部署、复现实验并上传 GitHub 的完整工程项目。  
实施原则：按工程依赖逐块实现，按知识依赖逐块学习；不设开发工期，不因时间或开发预算裁剪完整目标。

> 本文是待实施计划。模块验收项、实验设计和指标口径不代表已经实现或取得效果。阶段检查点用于学习、集成和纠错，不能代替最终完整交付。运行时的超时、调用上限、资源限制和费用统计属于可靠性及公平评测机制，继续保留。

## 1. 项目目标、边界与完成定义

### 1.1 业务任务

面向产品质量分析、售后分析和行业研究人员，调查美国汽车投诉、召回及可获得的官方调查材料。最终项目保持这一领域边界，避免把跨行业适配混入主要实验。

代表任务：

> 使用指定数据快照，调查某品牌、车型、车型年及事件时间范围内的制动相关投诉，核对相关召回与调查材料，解释关联依据、支持证据、反例、适用条件和未确认问题。

最终报告包括调查口径、结构化统计、证据卡片、时间线、类型明确的关联、逐项结论、未确认条件、数据版本和执行记录。

必须遵守的业务边界：

- 投诉是报告线索，不直接等于已确认缺陷；没有合适分母时不将投诉数称为故障率。
- 车型、年份、部件或症状相同，不直接证明投诉由某次召回解释。
- 没有检索到召回不等于没有缺陷；查询结果为空还需区分数据缺失、过滤条件和来源不可用。
- 车型层面的召回信息不直接确认具体车辆适用性。缺少生产日期、配置等条件时保留未知状态；VIN 查询不是本项目必需能力。
- 正式结论必须回到固定版本的原始记录。摘要、历史记忆和子 Agent 的陈述均不能替代原文。

### 1.2 完整能力范围

| 能力 | 最终实现要求 | 效果判断 |
| --- | --- | --- |
| 数据与证据治理 | 快照、时间语义、实体规范化、关联类型、引用定位、发布版本一致性 | 确定性测试与人工核查 |
| 检索 | BM25、dense、hybrid、hybrid+rerank；可按配置切换 | 比较召回、排序、质量与成本 |
| Agentic RAG | 基于证据缺口选择工具、继续检索、核对条件与重规划 | 与具备同等数据访问能力的固定流程比较 |
| 多 Agent | 数据调查与文档调查两个角色、独立上下文、按需委派和矛盾核对 | 与单 Agent 及单 Agent 并行工具比较 |
| 上下文 | 工件存储、分页读取、结构化摘要与原文回查 | 检查反证和约束保留情况 |
| 三类记忆 | 语义、情景、程序性记忆的建立、检索、失效、撤销和评测 | 比较正确复用与错误复用 |
| 执行可靠性 | 授权、计划修订、持久化、取消、预算控制、故障恢复 | 故障注入与状态一致性检查 |
| 产品与开源 | 可操作界面、真实演示、文档、CI、复现入口、GitHub Release | 干净环境验收 |

所有能力都要有实现、测试和实验记录。某项机制未带来质量收益时，仍应完成机制验证与负结果分析，调整默认启用策略；不能伪造收益，也不因缺少收益继续扩大无效调用。

### 1.3 最终完成定义

1. 固定快照可以重建结构化数据库、文档块和检索索引。
2. 单个任务与所有子任务绑定同一数据发布版本，所有正式结论能定位原文。
3. 四类主基线、必要消融、故障实验和记忆实验完成，结果逐题可追溯。
4. 多 Agent、三类记忆、上下文管理与恢复均有真实集成案例。
5. 声明支持范围内的硬约束测试全部通过；质量目标由开发集确定并在测试前冻结。
6. GitHub 仓库含可运行代码、最小示例、数据获取说明、学习记录、实验报告和发布版本。
7. 另一位使用者能够根据文档完成启动、调查、评测与故障演示。

## 2. 实现与学习组织方式

### 2.1 每块统一完成流程

按“学习原理 → 手工完成一个例子 → 实现最小接口 → 接入已有系统 → 验证成功与失败路径 → 记录取舍 → 提交代码”推进。

每个模块保留一份学习记录，包含：

- 解决的问题、前置知识和输入输出；
- 用自己的话解释原理，画出一条真实数据或控制流；
- 一次手工跟踪、一次有意义的失败案例；
- 实际验证结果、限制和替代方案；
- 本模块新增代码、依赖以及对应 Git 提交。

模块契约先用少量固定样例验证；模型依赖可以使用确定性假实现，以隔离业务逻辑问题。模拟结果只用于工程测试，不能代替真实模型质量实验。仅对重要边界、故障和算法行为编写测试，避免为文案或简单透传重复实现逻辑。

## 3. 技术结构与关键契约

### 3.1 推荐技术栈

| 层 | 实现起点 | 使用边界 |
| --- | --- | --- |
| 服务与契约 | Python、FastAPI、Pydantic | 参数校验、领域对象与 API |
| 编排 | LangGraph | 图内分支、状态与中断，不替代授权和持久化任务调度 |
| 业务与控制数据 | PostgreSQL、迁移工具 | 查询、计划、授权、任务、证据、记忆和事件 |
| 检索 | BM25、Qdrant、RRF、一种 reranker | 分阶段增加并分别测量；统一数据发布版本 |
| 原始文件与工件 | 不可变文件目录、哈希清单 | 原文、解析结果、日志、摘要源和评测工件 |
| 文档处理 | HTML/Markdown 解析、按资料需要加入 PDF 解析 | PDF、OCR 等是否需要由实际资料确定 |
| 模型 | 一个主模型、一个 embedding 模型 | 锁定标识和参数，保留替换接口 |
| 后台执行 | 数据库任务表与 worker | 领取、租约、执行代次、取消与结果提交 |
| 产品与部署 | React、Docker Compose、pytest、GitHub Actions | 先命令行/API，后界面；CI 分离离线与模型评测 |

版本在选型验证后写入锁文件和实验清单，不在计划里猜测“最新版本”。MCP、图数据库、模型训练和跨行业扩展属于独立扩展，不作为本项目完整交付前提。

| 对象 | 必需信息 |

| DatasetRelease | release_id、原始快照、映射版本、解析版本、BM25/向量索引、模型与配置摘要、完整性状态 |
| Evidence | release_id、原始版本、原文位置、摘录、实体范围、时间范围、支持/反对/中立角色 |
| Claim | 原子结论、范围、证据组合、反证、未确认条件、验证状态 |

字段可以从基础必需项逐步增加，但早期接口应预留稳定 ID、版本和来源引用。通过迁移演进，不重写已有实验记录。

### 3.3 时间规则

支持两种明确区分的模式：

| 模式 | 含义 | 数据条件 |
| --- | --- | --- |
| snapshot_analysis | 在一个固定快照里调查指定事件区间 | 固定 release_id；报告同时展示事件区间和快照日期 |
| historical_as_of | 只使用在指定知识截止时间之前可证明已公开的内容版本 | 版本级公开/归档证据；无法证明的内容排除或返回不支持 |

事件发生时间、机构接收时间、公开时间和本地首次观察时间不能互相替代。首次观察可证明该版本在观察时存在，不能反推更早公开时间。后来下载的文档即使标注较早发布日期，也需要验证具体内容版本，而不能默认排除后续修订。

historical_as_of 的过滤与拒绝机制属于必做功能；实际历史覆盖范围依据可验证资料声明。若缺少真实历史归档，使用带明确来源说明的受控测试验证机制，不能宣称已支持任意历史日期。

### 3.4 关联与证据规则

关系类型至少包括 scope_overlap、symptom_similar、officially_referenced、excluded_by_scope、applicability_unknown。确认状态指该类型关系是否成立，不等于因果关系成立。

每种关系规定：所需字段、证据组合、否定条件、未知值处理和允许输出的措辞。官方文件显式引用也只支持文件实际陈述的关系。后续结论仍需独立语义校验。

证据标注以原子结论为单位，支持“若干可替代证据集合”和“必须联合出现的证据”。单条引用存在、某个证据组合足够、整份调查完整，是三个不同的验收层次。

### 3.5 发布一致性与授权规则

原始快照、映射、文档块和索引在构建时绑定同一 dataset_build_id。发布清单完整并校验成功后，才生成不可变 release_id 并切换默认入口。任务开始时固定 release_id，所有工具和子任务继承；不能在某索引缺失时静默退回 latest。

授权与计划修订分离。允许范围内的新假设和步骤可产生新修订并继续执行；数据范围、工具权限或运行限制扩大时获得新授权。每次执行、恢复和提交都检查授权有效性。旧修订结果保留审计记录，是否复用需重新验证适用性；撤销授权后的结果不得自动发布。

仓库文档、投诉、PDF、网页、工具日志和检索摘要都属于任务数据，不能修改授权、用户目标和系统规则。

## 4. 分模块实现与学习

### P1-00：任务设计、人工调查与评测草案

**依赖：**无。

**学习重点：**业务问题转为可验证任务；事件时间与知识时间；正确性、完整性和拒答的区别。

**实现内容：**先人工完成约 10 个探索任务，覆盖直接查询、跨源关联、证据不足、条件歧义和反例。建立任务 Schema、证据标注规范及初始开发/测试划分规则。正式任务集建议从约 60 个不同任务逐步构建，数量根据独立事件覆盖确定，不将同一事件改写充数。

**动手练习：**分别写出“有投诉但未确认缺陷”“存在相似召回但范围不符”“需要补充条件”的调查说明。

**产物：**任务模板、人工调查样例、标签定义、评分草案和来源获取清单。

**验收：**每题有明确范围、可接受输出、禁止推断和缺信息行为；开发题与测试题按事件/召回簇隔离。探索阶段可人工查看公开网页，正式评测只能使用后续冻结的允许数据。

### P1-01：工程骨架、契约与最小运行观测

**依赖：**P1-00。

**学习重点：**领域对象、类型校验、数据库迁移、结构化日志、依赖注入和契约测试。

**实现内容：**建立后端包、配置加载、迁移、模型适配器、工具接口、工件存储和基本事件记录。预留 release_id、grant_id、revision_id 和 task_id。实现最小运行限制与工具白名单；早期演示使用开发配置中的明确只读权限。先保存基础记账和事件，后台调度在 P1-11 完善。

**动手练习：**通过一个假查询工具返回带来源 ID 的结果，追踪请求到工件；注入字段缺失和工具错误。

**产物：**可启动服务、命令入口、契约模型、初始数据库迁移、开发测试夹具和离线 CI。

**验收：**非法输入被拒绝；日志能关联任务与调用；配置不硬编码密钥；真实模型调用与假实现可明确区分。

### P1-02：数据获取、快照与时间语义

**依赖：**P1-00、P1-01。

**学习重点：**幂等导入、来源血缘、增量更新、内容版本和历史可见性。

**实现内容：**接入 NHTSA 投诉、召回和实际可获取的调查材料，固定字段字典及下载策略。保存原始文件、哈希、来源条件和时间字段，解析失败单独记录。增量更新创建新版本，不覆盖旧内容。落实第 3.3 节的两种时间模式。

同时制作资料可用性矩阵：是否可下载、是否可解析、是否能定位原文、是否提供结构化记录之外的信息。缺少调查材料时扩大领域内的真实样本寻找，不生成虚构资料冒充原文。

**动手练习：**对同一原始快照导入两次；构造迟到记录、历史修订和未知公开时间。

**产物：**原始快照 manifest、字段字典、时间映射表、数据质量报告、可用性矩阵。

**验收：**导入幂等、记录数可对账；当前快照历史分析不会被标注为历史时点还原；历史可见性不明时明确排除或返回不支持。

### P1-03：实体标准化、结构化查询与关联类型

**依赖：**P1-02。

**学习重点：**实体消歧、关系语义、参数化查询、重复计数和未知值逻辑。

**实现内容：**规范品牌、车型、车型年、生产日期、配置与部件，保留原值。提供预定义只读统计工具；模糊匹配只生成候选。实现第 3.4 节关系类型与晋升规则，所有关联绑定证据和版本。统计优先来自结构化全集，不能用 top-k 检索结果代替总体计数。

**动手练习：**制造一条投诉对应多个部件的 join 放大；比较同车型年、同部件但不同缺陷的两次召回。

**产物：**映射规则、EntityLink 实现、查询 API、手工核对的答案集。

**验收：**去重口径一致；未知生产日期不会被当作落入范围；精确字段匹配不能晋升成未被证实的因果关系。候选、排除和确认依据均可展示。

### P1-04：文档解析、分块与引用定位

**依赖：**P1-02、P1-03。

**学习重点：**结构解析、父子块、限制条件保留和稳定引用。

**实现内容：**短投诉整体保留；长文档按标题、段落、表格分块，保留父块。建立固定长度对照版本。文档版本、页码/段落/偏移、文本哈希和原文路径一起保存。根据真实资料加入 PDF 解析；若需要 OCR，记录识别方式和不确定文本，不直接将 OCR 猜测作为可靠原文。

**动手练习：**找到一处跨页或跨段限制条件，展示错误分块如何改变适用范围。

**产物：**解析器、两套分块配置、检查页、引用定位器和解析失败清单。

**验收：**表格、否定条件和车型范围可人工复核；同一 URL 的新版本不能替换旧引用；引用可以还原到固定原始文件。

### P1-05：BM25、向量、融合与重排

**依赖：**P1-03、P1-04。

**学习重点：**稀疏/稠密检索、RRF、reranker、过滤与排序的不同职责。

**实现内容：**依次实现 BM25、dense、hybrid、hybrid+rerank，统一查询和返回结构，保留各阶段候选日志。记录模型、索引、配置和数据构建版本。已确定违反任务范围的内容不能作为适用证据；元数据缺失的资料可进入单独的待核查候选通道，不能直接当作已匹配。允许在授权范围内展开关联文档。

**动手练习：**分别诊断“没有召回”“召回但排序靠后”“条件过滤错误”三种失败。

**产物：**检索服务、相关性标注、候选轨迹、检索实验表。

**验收：**比较 Recall@k、nDCG@k、错误年份命中、精确编号命中和时延；测出重排没有收益时保留可切换实现并记录默认策略。模型和参数选择仅用开发集。

### P1-06：数据发布清单与跨存储一致性

**依赖：**P1-02～P1-05。

**学习重点：**不可变版本、构建与发布分离、完整性验证和任务级一致性。

**实现内容：**把数据、映射、解析结果、BM25、向量索引及配置组成 DatasetRelease。各组件校验完成后发布清单，再在控制数据库中原子切换默认 release_id。查询入口只接受完整发布版本；旧任务固定原版本。回收旧数据前检查活跃任务、报告引用及保留策略。

**动手练习：**任务执行中发布新数据；模拟向量索引未构建完和工件哈希不匹配。

**产物：**发布构建器、验证器、版本目录、任务绑定接口和回滚入口。

**验收：**长任务继续读取原发布版本，新任务可用新版本；构建失败不影响已发布版本；跨数据库和索引的版本混用被检测并阻断。

### P1-07：Claim/Evidence、评分与固定调查流程

**依赖：**P1-00、P1-03、P1-06。

**学习重点：**原子结论、引用支持、证据组合、盲评和强基线。

**实现内容：**实现证据对象与结论校验器。固定流程包含结构化查询、适用范围过滤、文档检索、必要的关联展开和回答生成，具备与后续 Agent 相同的数据访问能力。程序检查引用存在、版本、范围和时间；人工标注语义支持、反证处理和完整性。

正式标签记录可接受证据组合、等价证据、范围条件和禁止推断。新增有效证据采用预先规定的盲审规则，对所有方法一致处理。

**动手练习：**给出“引用真实但结论过强”和“单条不足、两条联合足够”的例子。

**产物：**固定流程基线、证据卡、评分脚本、基线结果和人工争议裁定记录。

**验收：**无相关记录、条件不足、反例、引用失效均得到不同且正确的处理；发布完整性与引用校验不依赖模型自我声明。

### P1-08：授权、Plan Mode 与持久化任务状态

**依赖：**P1-01、P1-07。

**学习重点：**用户授权与计划版本的区别、状态机、执行层检查和提示注入边界。

**实现内容：**落实 Authorization 与 PlanRevision 分离。建立 DRAFT、WAITING_INPUT、WAITING_APPROVAL、RUNNING、PAUSED、COMPLETED、FAILED、CANCELLED 等合法转换。任务生命周期与调查结果质量分开：COMPLETED 不自动表示证据充分。

Plan Mode 允许只读调研、澄清和保存计划；生成正式交付进入执行阶段。产品可对范围明确的只读请求按用户提交的范围建立授权，对新增范围显式确认。禁止通过普通文档内容生成授权。

**动手练习：**范围内修改假设、扩大车型范围、撤销授权后恢复、PDF 中夹带伪造批准指令。

**产物：**授权服务、计划修订、状态机、问答/审批接口与权限测试。

**验收：**直接 API 和子任务都不能绕过检查；合法修订可继续；旧授权撤销后不能执行或发布；缺少关键业务条件时进入等待而非猜测。

### P1-09：单 Agent 的 Plan/Execute 与 ReAct 闭环

**依赖：**P1-07、P1-08。

**学习重点：**计划分解、工具选择、观察驱动继续调查、停止条件与重规划。

**实现内容：**planner 维护目标、范围和证据缺口，executor 调度当前修订的任务，调查 Agent 在任务内选择工具。保存调查假设、支持/反对证据、未解决条件和每次计划变更依据。设置调用、重复、上下文和资源上限；耗尽时保存已完成结果并说明限制。

**动手练习：**首次检索不足后改写查询；发现反例后调整假设；遇到暂时超时执行有限重试。

**产物：**单 Agent 闭环、结构化决策记录、调查轨迹和对照结果。

**验收：**与 P1-07 使用相同数据、模型和运行限制；能够解释收益及额外开销；证据不足不会被更长回答掩盖。此阶段先同步执行，后台恢复在 P1-11 集成。

### P1-10：上下文构建、结构化摘要与原文回查

**依赖：**P1-09。

**学习重点：**信息选择、压缩损失、工件化与提示缓存的区别。

**实现内容：**按用户目标、授权限制、计划、关键证据、反证和最近动作构建上下文。大结果放入工件，支持分页与引用展开；摘要保存来源版本和否定条件。记录摘要调用及其费用。缓存只用于优化，不代替上下文裁剪。

**动手练习：**把一条重要反证放在长轨迹前段，比较完整历史、最近窗口和结构化摘要的表现。

**产物：**上下文构建器、摘要 Schema、日志分页和原文回查工具。

**验收：**车型、年份、否定条件和未确认项保持可见；摘要引用失效能被发现；恢复上下文能区分旧修订与当前修订。

### P1-11：持久化调度、预算预留、取消与故障恢复

**依赖：**P1-08～P1-10。

**学习重点：**至少一次投递、幂等、租约、执行代次、取消和全局预算。

**实现内容：**建立持久化任务队列、领取、心跳、重试、截止和取消。每次领取生成执行代次，结果提交使用任务版本与代次校验；旧 worker 不能覆盖当前状态。调用前原子预留共享资源额度，结束后结算，释放未用部分；不让各子任务独立占用全额上限。超时调用的实际费用未知时保留待对账记录，不直接当作零费用。

保存可恢复的任务、修订、授权、发布版本、工件引用和已完成调用。恢复先核对这些对象，再决定继续、等待或失败。取消后停止新调度，处理仍在运行的调用，拒绝迟到结果自动发布。无法保证上游停止时明确记录残留状态。

**动手练习：**worker 退出、重复投递、主服务重启、租约过期后旧 worker 恢复、多个任务同时申请最后一份额度。

**产物：**worker、恢复接口、资源账本、执行代次检查、故障注入器。

**验收：**无重复正式结果、无旧授权续跑、终态一致；迟到结果隔离保存；额度耗尽后不继续创建调用；不可恢复时明确失败。此处不声称跨外部服务 exactly-once。

### P1-12：按需多 Agent 与矛盾证据聚合

**依赖：**P1-09～P1-11。

**学习重点：**上下文隔离、委派契约、并发依赖、协作开销和冲突核查。

**实现内容：**实现数据调查与文档调查两个子 Agent。委派包含目标、release_id、授权、范围、输入证据、允许工具、资源分配和完成条件。返回结论、证据、反证、失败与待核实项；共享原始工件，不共享不断增长的整段聊天。

由主 Agent 对矛盾进行原文核查，不能多数表决。触发策略只使用当前任务可见特征，在开发集确定；保留关闭多 Agent 的配置。同步工具并发和独立子 Agent 分别实现，区分两者收益。

**动手练习：**两个子 Agent 对同一召回适用性得出相反判断；处理一方超时、一方成功和重复调查。

**产物：**委派 Schema、依赖图、聚合器、触发策略、真实复杂任务演示。

**验收：**四类主方法可在同条件下运行；简单任务无须强制委派；复杂任务能独立推进两个分支；矛盾未消解时保留未确认结论。真实资料不足时继续做资料可用性验证，并如实标记演示限制，不用合成文档冒充真实多源收益。

### P1-13：语义记忆与候选审核

**依赖：**P1-10、P1-11。

**学习重点：**事实、偏好、推测的区别；记忆作用域、来源、失效和派生索引。

**实现内容：**保存确认过的用户偏好、项目约定和经验证的领域操作规则。异步提取只创建候选；按来源与验证规则晋升。记忆绑定用户/项目作用域、数据版本条件和来源，支持修改、冲突处理、过期、删除和禁用。官方领域事实仍以业务证据库为准，记忆只索引来源，不复制为独立真值。

**动手练习：**撤销错误偏好，更新一条随数据版本变化失效的规则，尝试跨用户检索。

**产物：**Memory CRUD、候选队列、审核接口、作用域过滤及撤销传播。

**验收：**删除后活动检索索引和适用缓存不再返回；错误事实不会因被多次摘要而变成确认事实；历史报告保留审计状态，但不得再把已撤销记忆供新任务采用。

### P1-14：情景记忆、历史任务搜索与浏览

**依赖：**P1-13。

**学习重点：**相似性与适用性的区别、事件序列、失败经验复用和按需展开。

**实现内容：**保存调查摘要及事件索引，包括范围、版本、尝试、反证、结果与失败。支持跨任务搜索、任务内搜索、最近任务浏览、以事件 ID 为锚点查看相邻片段。先过滤权限和适用范围，再按症状检索。历史结论仅作线索，使用前重新核验当前数据。

**动手练习：**用“同车型相似现象但不同年份”和“历史调查已否定的假设”验证错误类比。

**产物：**历史检索工具、浏览接口、任务摘要与记忆采用事件。

**验收：**相关历史可被找到，不适用历史可被忽略；保留失败标签；默认返回概要，必要时展开原文；不能把历史调查的最终结论直接写进当前报告。

### P1-15：程序性记忆与可验证 Skill

**依赖：**P1-13、P1-14。

**学习重点：**可执行流程的前置/后置条件、迁移验证、版本和回滚。

**实现内容：**从多次成功且可独立验证的调查流程提出候选 Skill，包含参数、前置条件、允许工具、动作、后置条件和失败处理。生命周期为 candidate→validated→enabled→deprecated/revoked。验证通过后才启用；Skill 作为计划建议进入授权检查，不能增加权限。

**动手练习：**把“核对某类召回适用范围”写成流程，在不同事件上验证；故意删除前置条件观察误触发，再停用该版本。

**产物：**Skill Schema、候选提取、验证集、版本管理和回滚工具。

**验收：**至少有来源任务之外的迁移验证；版本过期、前置条件不满足和恶意流程内容被处理；与普通文字经验对比。单次成功只能形成候选，不能宣称已学会通用流程。

### P1-16：综合评测、消融与失败归因

**依赖：**P1-00～P1-15。

**学习重点：**公平基线、配对比较、统计单位、时序隔离和负结果解释。

**实现内容：**按第 5 节冻结系统与数据版本，执行四类主方法、检索与上下文消融、三类记忆对照、故障挑战和外部文本干扰测试。先运行主比较，再围绕真实问题增加消融，避免无解释价值的全组合。

**动手练习：**从一次看似提升的结果中检查额外调用、不同数据权限、任务排除和记忆污染；复盘一个性能退化任务。

**产物：**实验 manifest、逐任务结果、质量—成本图、置信区间或样本局限说明、失败报告。

**验收：**所有数字可回到日志和工件；测试集不用于继续调参；无收益的机制明确记录适用范围与默认策略；人工评分可复核。

### P1-17：交互产品与端到端验收

**依赖：**P1-16；基础界面可从 P1-07 起逐步建设。

**学习重点：**状态展示、证据交互、错误可解释性和可复现产品体验。

**实现内容：**展示调查条件、时间模式、数据发布版本、计划/授权、实时进度、证据卡、关系类型、原文定位、历史任务、记忆来源和执行回放。区分运行终态与证据质量。用户能澄清、取消、恢复、查看未确认条件和撤销记忆。

**动手练习：**让另一位使用者只按 README 完成调查并追到原文；让其识别一次部分失败。

**产物：**完整前后端、容器启动配置、演示脚本、录屏和用户说明。

**验收：**简单查询、复杂调查、反证、澄清、取消恢复、错误记忆撤销均有真实工件；不以成功样式掩盖证据不足；API 与 UI 遵守同一权限与版本规则。

### P1-18：GitHub 仓库整理、复现与正式发布

**依赖：**P1-16、P1-17。

**学习重点：**开源工程组织、许可证边界、CI、发行版本和可追溯成果表达。

**实现内容：**按第 6 节准备仓库，完成干净环境复现、测试、依赖和敏感信息检查。整理个人实现与复用内容。最终上传 GitHub，建立版本 tag 和 Release，附代码版本、数据获取方式、实验入口与已知限制。

**动手练习：**在不使用本机缓存和绝对路径的环境中复现；从 README 的结果表追溯一条指标到任务和工件。

**产物：**完整 GitHub 仓库、Release、数据说明、实验报告、贡献清单和演示链接。

**验收：**仓库可被第三方克隆并启动；离线检查可运行；需要凭证的模型评测有单独说明；无密钥、个人工作区路径或不应公开数据；上传完成并验证远端内容。仓库所有者、名称及可见性在实际发布时确定，不在本计划中虚构地址。

## 5. 评测协议

### 5.1 任务与评分

探索集用于学习，开发集用于参数与策略选择，测试集用于冻结后的评价。按事件/召回簇划分，不让同一事实的问法改写跨集合。

正式任务至少覆盖直接查询、跨源调查、条件不完整、证据不足、反证、时间边界、错误关联和工具故障；自然任务与人工故障变体分开统计。人工评分尽量隐藏方法名称，争议样本二次复核。

| 指标 | 口径 |
| --- | --- |
| 证据 Recall@k | 必需证据单元或可接受证据组合的覆盖；等价证据映射提前规定 |
| nDCG@k | 按分级相关性评价排序；不替代最终结论质量 |
| 引用支持率 | 支持的引用—结论对 / 已评价引用—结论对；部分支持单列 |
| 无依据断言率 | 缺少足够支持的可验证断言 / 所有被评价的可验证断言 |
| 关系判断 | 各关系类型的正确、错误、漏判及未知处理；不能只靠少提关系提高精度 |
| 任务完成率 | 满足该题全部必需条件的任务 / 冻结评价任务；排除规则预先规定 |
| 拒答与澄清 | 必须停止/询问时的正确处理及不必要拒答 |
| 恢复 | 支持范围内故障任务达到有效终态的比例；正确结果与安全终止分开 |
| 成本与时延 | 模型、重排、摘要、记忆等全链路开销；人工等待单列 |

质量目标在开发集建立基线后写入版本化协议，再冻结测试。硬约束在声明测试集内全部通过，但不扩大解释为未知场景的绝对保证。

### 5.2 对照与消融

| 实验 | 方法 | 控制条件 |
| --- | --- | --- |
| 调查机制 | 固定流程 / 单 Agent / 单 Agent 并行工具 / 多 Agent | 同模型、数据、允许工具、评价规则和运行额度；方法实际开销另报 |
| 检索 | BM25 / dense / hybrid / hybrid+rerank | 相同标签、数据发布版本和候选范围 |
| 上下文 | 完整历史 / 最近窗口 / 结构化摘要 | 同任务和模型上下文容量；过长输入的处理规则预先规定 |
| 记忆类型 | 无记忆 / 语义 / 语义+情景 / 三类全开 | 冻结历史或同一任务前缀，重跑前重置 |
| 执行可靠性 | 正常 / 故障注入 / 恢复机制关闭 | 同故障类型与语义触发阶段，记录未触发事件 |
| 可信边界 | 晚到记录、版本更新、错误关联、注入文本、旧授权、旧 worker | 确定性判定与少量人工复核 |

记忆实验分“冻结历史检索”和“顺序积累”两种设置。历史仅来自允许的早期调查及当时可见证据，不包含当前目标答案或未来版本结果。顺序积累中各方法可能形成不同记忆，应报告为系统整体效果。评分标签不能回流给模型或候选记忆提取。

### 5.3 结果解释

统计单位以独立任务或事件簇为主。重复运行评估随机波动，不增加独立事件数量。展示逐题配对变化、实际解决数、分类型结果和样本局限。

持续记录计算与人工标注开销用于工程分析，不据此设置开发工期。多 Agent 在调用前预留共享运行额度；预算、取消、无新证据和授权变化均可终止任务，并保存已完成工作。

dependency-lock-file 表示所选依赖管理工具的真实锁文件，实施时替换为实际文件名。大原始数据、完整模型缓存和数据库文件不直接提交源码仓库；提供来源、校验值、下载脚本和允许公开的最小样例。数据再分发依据来源条件决定，不将代码许可证套用到第三方数据。

### 6.2 README 与复现入口

README 必须回答：项目解决什么问题、支持什么范围、如何启动、如何取得数据、如何运行一个任务、如何查看证据、如何复现实验、哪些结果未得到证明。

提供以下真实命令入口并在实现完成后填写确切语法：

- 安装与环境检查；
- 数据下载、校验、构建及发布；
- API/UI 启动；
- 单题调查、计划批准、取消与恢复；
- 四类方法评测、故障注入和记忆重置；
- 离线验证与完整模型评测。

命令在实现前是接口要求，不能把尚不存在的命令写成已经可运行。

### 6.3 CI 与发布

普通提交运行无密钥的格式/类型、契约、关键单元和小型集成检查。外部模型及完整数据评测通过受控手动任务运行，保留运行标识和结果；不要让来自不可信分支的任务获得模型密钥。

发布前从干净环境验证数据构建与至少一条完整调查，扫描当前内容及拟上传历史中的敏感信息，检查第三方许可证和归属。上传后验证默认分支、tag、Release、文档链接和克隆启动。后续发布必须可对应到代码版本和实验版本。

## 7. 学习成果与个人贡献表达

按模块掌握：

- 数据：从结论反查原文、说明版本和时间；
