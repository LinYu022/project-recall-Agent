# 数据获取与更新策略 v0.1

本策略对应 P1-02 当前适配器和显式探索来源，不构成正式 DatasetRelease 或全量统计覆盖。

## 已实现的获取范围

| 类别 | 固定选择 | 对象与边界 |
| --- | --- | --- |
| 召回 | campaignNumber=10V039000 | 保存该请求全部 results；不把车型行数当召回事件数 |
| 投诉 | FORD / F-150 / 2016 | 保存该车型查询响应；不等于制动投诉集合或全国投诉全集 |
| 调查资料 | PE10006 closing resume 的固定官方 URL | 保存实际文件字节；原文位置随内容哈希固定 |

来源配置为 `examples/nhtsa-sources.json`。所有来源属于 exploration_only，已人工查看的事件不进入未见测试集。官方入口与字段说明见 `docs/data/source-field-dictionary-v0.1.md`；获取时间和指纹见原始快照观察清单。

## 传输与失败

当前适配器仅对注册表中的来源发请求：单响应 2 MiB 上限，30 秒套接字超时，显式请求 identity 编码，读取长度核对，不自动重定向，不自动重试。每次 capture 是一次独立尝试；人工重试也生成新清单。失败不会记作零记录；有完整响应时保留原 body，无完整 body 时只留失败元数据。磁盘错误直接报错。

本模块没有定时抓取、并发采集或通用压缩/批量文件导入。30 秒不是总下载期限；响应上限要按新来源预检后调整。没有声称适配器支持官方目录里所有大体积 zip。

## 内容更新与重放

1. 更新时重新 capture 到同一根目录，增加获取清单；相同 body 复用哈希对象，不修改旧内容。
2. 对新 snapshot_id 执行 inspect，查看接受/拒绝、日期标记和批次指纹。
3. 导入使用固定 mapping_version；新内容增加记录版本，重复导入同一清单返回 already_imported。坏行保留原始位置与错误码。
4. 修改字段策略必须增加 mapping_version。新名称、缺字段或记录消失不自动解释为实体变更、撤回或删除。
5. 任务检视明确列出 snapshot_ids。新增抓取和入库不会改变之前固定的输入；正式发布的构建、完整性检查和默认版本切换在 P1-06 完成。

## 正式数据范围扩展

正式开发题的数据范围须由任务集确定，记录车型/车型年/召回簇、事件区间、来源选择及抓取批次。扩大范围时将更多来源加入版本控制的注册表，先检查响应形态、字节上限、是否有分页或截断信息，再做数目对账。当前 API 的 count=results 长度只证明响应内对账，不能证明外部总体完整。

需要全集统计时，应评估官方批量文件及对应字段字典，另写其格式适配器，再测独立 ODI、部件行和产品行的计数口径。不能把当前小样本或未来检索 top-k 充当统计全集。P1-03 实现查询口径时继续落实这些约束，P1-06 发布时冻结实际范围。

调查资料已取得一份可读取且提供额外信息的真实文件，所以本轮无需用虚构原文弥补缺口。后续若任务范围内缺材料，应记录无法获取/无法解析原因，沿官方目录扩大真实样本寻找；仍不能宣称覆盖全部调查文书。

## 时间证据边界

事件、提交/接收、文档标注日期、HTTP 缓存头、首次观察、抓取时间分开保存。`historical_as_of` 仅接纳所选清单中截止前实际取得的具体内容版本；目前无独立的早期历史归档，不能还原任意过去日期。

本地首次抓取可证明该版本在那个时刻可被取得，不证明更早公开时间。日期未知或版本冲突的排除/不支持结果，必须与真正的区间外空结果区分。没有用更新时间、事件日期或模型判断补出公开日期。
