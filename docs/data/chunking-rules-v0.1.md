# P1-04 分块与上下文规则 v0.1

适用：固定原始版本的 PDF/JSON 文本；当前不是正式 DatasetRelease 或检索效果评测。

## 两套配置

| 配置 | 切分方式 | 共享能力 |
| --- | --- | --- |
| examples/chunk-structure.json | 已审查 PDF 按章节、段落、整表；JSON 长叙述按空行段落 | 固定来源、原文位置、父块、范围上下文、引用回放 |
| examples/chunk-fixed.json | 每页/字段按 700 个 Python Unicode 字符切窗，重叠 100；不跨字段拼接 | 同上；不通过剥夺基线的上下文访问来制造差异 |

两者对长度不超过 4000 字符的投诉采用同一例外：整个 summary 作为一个叶块，保留全部空白和叙述。超过阈值时结构化方案保留段落；单段很长也不截断。固定方案才切窗。700/100/4000 是版本化教学初值，未声称是最优参数；P1-05 以后仅用开发集选择参数。

## 结构审查与失败边界

`examples/chunk-structure-rules.json` 按 source_version_id + parser_sha256 选择审查配置。每个章节/子块都保存固定单元 ID、字符半开区间和原文片段哈希；新版本不能凭同 URL 自动继承旧结构。

结构配置由实现代理逐项对照完整原页编写，不是独立人工金标准，也不是通用 PDF 标题/表格识别器。未审查 PDF 的结构化分块拒绝执行；固定方案可作为 layout_not_reviewed 的候选对照，后续调查不能据此声称布局已核验。后续正式语料纳入前继续审查并扩充配置，不用静默猜测替代缺失结构。

章节和引用片段须按文档顺序排列，不得重叠；子块必须落在其章节父块内。必需上下文 key 必须存在，依赖不得有环。部分解析、范围越界、文本哈希变更、表格版式不符都会停止构建，不输出一个假装完整的块集合。

## 父子块与上下文

PDF 结构树为 document → section → paragraph/metadata/table。固定方案为 document → page/field → window。document 根保留全部已解析文本；root 和父块不参加叶块检索。结构化方案有审查过的 title_path，固定窗口保留其页/字段位置。

`parent_id` 固定直接父块；`required_context_ids` 显式指出还需展开的范围章节。`expand_chunk` 返回焦点块、完整直接父块和递归必需上下文，不默认把长 PDF 全部塞进上下文；完整根仍可通过 ID 回查。保留这些关系不代表所有条件已被识别或某个具体结论已受支持。

本例后文使用 subject vehicles，完整车型范围写在 MANUFACTURER & PRODUCT INFORMATION。因此正文章节和统计表均关联此前的范围章节。固定窗口也能使用该范围和完整页父块；比较的是切分边界，不是可访问资料差异。

JSON 投诉另外携带来源 products/components 元数据；召回各字段的子块保留其他叙述字段的上下文，避免只看到 Remedy 中的代词。元数据是原始值，实体规范值和适用性判断仍使用 P1-03 规则，不能混成自动因果推断。

## 表格与跨页片段

当前真实表格使用已审查的列名/行标签/脚注模板：整表不拆分，列名、行数、每行值数量、数字格式、脚注存在性全部检查。数字原字符串保留，逗号去除后提供整数，并保留每个数值的原页字符位置。缺值、未知符号或列名变化直接拒绝。

模板目前只支持单个来源范围中的数字表；跨页段落/章节可由多个 TextRange 组成，逐段保留页码和原文偏移。跨页表格需要独立审查模板，不自动拼列；此边界会在模块验收记录中保留。真实材料只有一页，跨页机制使用明确合成的多页 PDF 验证，不声称实测了真实跨页表格。

多个来源片段展示时以两个换行拼接，text_join_policy 明确记录这一点。拼接后的字符串位置不能直接作原文偏移；`cite_chunk` 为每个来源片段返回一个独立 Citation，逐一调用已有定位器回放。不同页的摘录不会被伪造成一段连续原文。

## 版本、保存与检查页

ChunkSet 固定 parse_artifact_sha256、source_version_id、完整配置/结构规则及其指纹，节点 chunk_id 也包含这些绑定。相同内容重复保存复用工件；checked_chunks 从原始资料、解析器和分块配方重建，逐项比较保存结果。修改文字、删除上下文或替换配置会被检测。

解析工件继续保持 source-text/0.1 不变，新分块结果单独保存在 `.local/chunk-sets/artifacts/`。没有改写旧解析器、数据库或 API。索引/发布绑定分别在 P1-05/P1-06 完成。

`parsing/chunk_review.py` 生成本地检查 HTML：两套叶块、表格、原文位置和可展开上下文并列展示。原始文本经 HTML 转义；原布局文本采用横向滚动，不重排其列间距；输出文件不能覆盖。浏览器目视验证与程序字节回放分别记录，不把可读页面当作来源真实性的证明。

相关产物：`parsing/chunk_contracts.py`、`parsing/chunks.py`、`scripts/verify_chunks.py`、`tests/test_chunks.py` 和 `docs/verification/2026-10-26-chunks-real.json`。完整模块失败清单及最后验收仍待下一小步。
