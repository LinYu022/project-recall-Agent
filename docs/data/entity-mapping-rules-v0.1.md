# 实体映射规则 v0.1

对应 `examples/entity-rules.json`、`entities/normalize.py` 和 entity-rules/0.1。当前是探索范围内的小型项目目录，不是官方车型/部件本体，也不是覆盖所有品牌的标准化服务。

## 映射边界

| 字段 | 已实现规则 | 不能由此推出 |
| --- | --- | --- |
| 品牌 | Unicode NFKC、空白折叠、转大写；再与目录精确匹配 | 不依靠近似拼写确认品牌 |
| 车型 | 在已确认品牌的车型目录中精确匹配 | 不合并不同品牌相同型号，也不把 HS250H 自动并入 HS |
| 车型年 | 严格四位数字/整数，1886～2100；9999 保留未知 | 车型年不代表生产日，布尔和浮点值不当成年份 |
| 投诉部件 | 当前 API 的逗号分隔标签，保留每个原位置 | 多个部件位置不等于多条投诉 |
| 召回部件 | 整段描述保留，逗号不作分隔符 | SERVICE BRAKES 与其带 AIR 子类的长描述不自动视为相同精确标签 |
| 生产日期 | 目前支持的结构化字段未提供，标 unknown | 不用车型年、摘要内数字或默认日期填补 |
| 配置 | 当前未从自由叙述抽取，标 unknown | 不把投诉自述中提到的排量或配置当作已确认条件 |

名字的映射结果均保存 raw、canonical、status、candidates。未知标签包括空值、UNKNOWN、UNKNOWN OR OTHER、N/A；canonical=null。近似匹配的分数只是字符串相似度，最多返回三个候选；不能用于精确查询条件、适用性确认或因果结论。阈值 0.8 为当前候选提示参数，未作实体匹配准确率实验。

当前目录只显式列出 FORD/F-150、TOYOTA/PRIUS、LEXUS/HS 以及实际样例出现的部件标签。大小写/全半角/空白变化可以规范；F150 不会自动删除连字符后并入 F-150，只产生候选。不存在未经证据核对的车型别名表。后续扩大目录必须说明依据、变更 rules_version，并保留规则内容指纹。

## 持久化与血缘

`record_versions` 保存的原始字段和 source-record/0.1 映射不改写。另建 `entity_projections(version_id, rules_version)` 保存完整派生结果及 rules_sha256；`entity_vehicles`、`entity_components` 保存多值位置和可精确查询的 canonical 值。

同内容、同规则重复投影不新增；同规则名下内容漂移会被拒绝。新规则版本可并存，旧投影不被覆盖。外键将投影绑定回固定来源版本，再由 P1-02 的位置关联还原到原始快照。

本轮 0003 迁移增加三张表，没有改写 0001/0002。当前生产日期列保留 null；原值与未知原因位于投影对象。后续接入带可靠证据的生产日期/配置后再完善字段级规则与范围判断，本模块尚未完成。

## 计数口径

预定义 complaint count 只允许类型化条件，不接受任意 SQL。它先复用 P1-02 的固定时间选择，再验证所有投诉版本有对应规则投影，在数据库只读、可重复读事务中查询。

车辆与部件过滤用 EXISTS；总数按不同 ODI 记录键计。匹配部件位置数仅作诊断，不作投诉数。部件列表是“任一标签匹配”的并集，不能把各部件投诉数相加冒充不同投诉数。

生产日期条件通过区间比较检查，null 不满足区间；存在相关未知日期时返回 partial 并明确未知版本数。未请求生产日期过滤时，该未知数为 null、production_filter_status=not_requested，避免把“未检查”误写成“0 个未知”。历史选择不支持或有未解决问题时返回 unsupported、count=null，不假装成功零结果。

结果只覆盖固定的归档响应，population_completeness=not_established。统计没有使用 top-k 检索结果，仍不能据此声称完整总体、故障率、个车适用性或缺陷因果。
