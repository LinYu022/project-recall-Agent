## 由开发结果推导的数值草案

[版本化草案](../../evals/development-baseline-v0.1/quality-targets-draft.json)在本轮开发审查结束后生成，供另一版未见测试协议定稿使用，不能追认旧270格测试。暂按已测量开发点值给出“不退化”下限：

| 拟比较指标 | 开发点值/拟议下限 | 固定分母原则 |
| --- | ---: | --- |
| 处置合适 | 1.0 | 全部预先登记任务 |
| 生成任务核心完成，事件簇等权均值 | 1.0 | 全部预先指定的回答任务，不能剔除失败或未发出请求的任务 |
| 生成任务无保留条件满足，事件簇等权均值 | 0.75 | 只统计“满足”类别，保留有保留类别，不混入易停止任务 |
| 停止/有限回答相应阶段处理合适 | 1.0 | 独立的预先指定停止任务层 |

0.75来自Prius两题中1项无保留满足（1/2）和Ford一题无保留满足（1/1），再按事件簇等权：(0.5+1)/2=0.75。它既不是原始三题比率2/3，也不是把5项停止混入的7/8。这个类别指标不抹除联合调查“核心完成、轻微范围瑕疵”的原判断。

这仍是草案，不是已冻结完整新测试。原子无依据断言率、统一引用支持率、严格全义务任务成功目标未测量，继续null；不能编一个阈值冒称开发数据支持。只有2个事件簇，不报置信区间。拟议下限是否适合作验收要求，须结合下一版覆盖范围、独立标签和组件评分定稿，且须在新测试前完成；不得看新测试结果后调低。四种方法采用同一套定稿目标，不因这次只运行固定流程就删除其他方法或其消融。
