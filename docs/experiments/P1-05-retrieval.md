# P1-05 检索开发实验

日期：2026-10-26。最终后端：Qdrant 持久化本地精确模式；真实本地 ONNX 模型，无生成式模型或外部推理请求。

语料 225 条来源记录、593 个叶块、149 个去重证据组；12 个英语开发问题来自 4 个新召回事件。每题与其他同事件问题相关，不是 12 个独立事件。原探索资料作干扰项，未见测试集尚未建立。标签由实现代理按官方字段审查，未冒称独立人工金标准。

四种方法在 4 条精确编号题上均为 4/4 命中；4 条指定年份查询的错误年份命中均为 0。未指定年份的题目不被当作错误年份测试。元数据未知的待核查通道单独输出，不混入这些 matched 指标。

hybrid+rerank 的 nDCG@5 增量为 0.0473，Recall@5 没有下降，但预热中位耗时约为 hybrid 的 112.4 倍，超过事先规定的 5 倍门槛。因此默认 hybrid，重排保留实现和开关。

BM25 在此批开发资料上的 nDCG@5 高于 hybrid，hybrid 的 Recall@5 略高；没有宣称融合普遍更优。默认基线及重排启用规则均在结果之前保存，不能看完测试再选择。当前只有四个独立事件，不以这组结果证明普遍优势或中文效果。

协议：BM25 k1=1.2、b=0.75；各通道候选 30，RRF 常数 60，重排最多 30；相同语料、范围、标签和证据访问能力。每种方法先预热，每题 3 次，汇总每题中位数；模型加载/建索引不计入查询时间。最终比较与构建、回归、HTTP 检查顺序运行，未并发执行其他验证脚本；仍只是本机开发观测，不是生产吞吐基准。

两种真实模型均使用固定修订的 int8 ONNX、CPU 单线程、批量 8。编码模型为 384 维、上限 256 token，索引 593 个输入中 28 个截断。交叉编码器上限 512 token，query 超过 128 token 明确拒绝。截断有记录，完整引用仍从固定原文回放。

先完成 NumPy 参考，回查推荐栈后补齐 Qdrant。本次后端修订没有改变标签、参数和启用门槛。真实 Qdrant/NumPy 在 593 点全集和 198 点子集上对账，最大绝对余弦差异小于 8e-8；最终四方法质量指标与参考一致。Qdrant 本地模式采用精确扫描，未测试远端服务或 HNSW，不把此结果扩大为服务器性能结论。

验证：新增 35 项合成/本地存储测试，累计 255 项无数据库测试通过；49 个选定源码文件 mypy、Ruff、迁移 SQL 生成通过。另有 14 类真实检索 HTTP、原有两组各 7 类回环 HTTP 检查通过，服务均关闭。无新迁移，既有 38 项 PostgreSQL 测试本轮未重跑。
