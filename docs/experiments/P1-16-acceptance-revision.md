# P1-16剩余验收与实验修订建议

原计划要求“质量目标在开发集建立基线后写入版本化协议，再冻结测试”。本批真实测试已执行，独立审查的当前系统开发基线与数值目标尚未在测试前建立。这是实验顺序缺口，不能用事后补一个阈值把本批追认成预先注册的质量验收。

已完成的真实批次、负结果和失败仍然有效，作为冻结执行记录与探索性分析保留。角色分离v0.2是独立、统一的事后评分修订，适用于全部方法；不会改变原生成、参考标签或默认策略。其余未审语义指标保留null。

本轮新增的历史开发审查确实来自人类：六条支持、answered合适、核心任务完成。它来自P1-09已经看过的开发实现，共准备4份历史报告，实际只审1份；不能当作当前冻结系统基线、未见测试或完整总体。原冻结测试另有1份人类负向整题评价，两者不能混算“成功率50%”。

建议将后续质量验收单独登记为P1-16的一次新实验修订，保留原模块全部目标：

1. 在开发侧建立明确覆盖缺陷条件、后果、补救、适用范围、关系、反证及正确停止的任务与原子义务。先核查原始证据与真实输入可见性；补映射或调整提示只在开发侧进行，保存新实现身份。
2. 由实际独立审查形成该实现的开发质量基线。提前约定“严格全部义务满足”和“核心要求完成”的区别、每项分母、争议处理与审查时长记录。按开发结果确定可解释的数值目标，缺基线时不先造数字。
3. 在版本化协议中冻结目标、模型/额度、方法、输入、参考义务、统计与来源隔离。此前20份测试资料已经被检查，应作为已见材料保留，不能再次称为未见测试。准备另一组按事件隔离的未见资料，并由人类核对标签与关键义务。
4. 在新资料、具体请求上限和费用范围明确后取得该批调用批准，再实际执行。旧P1-09和本批584次批准均不自动扩用；本轮为0次新增请求。
5. 同时报告全分母执行、机制实际触发、独立语义质量、资源与失败。无收益也完成实现与负结果分析；置信区间条件不满足就说明样本局限。

这份建议已具体记录，但尚未声称完成新开发基线、数值门槛或下一批实验。P1-17尚未启动；P1-18公开工件打包、干净复现及GitHub上传目标保留。学习者后续练习继续提供范例；独立人类判断与教学参考答案分别记账，不能让实现代理代填human。
