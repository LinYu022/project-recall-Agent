## 首轮问题与修复记录

失败与被替代的运行留在 `.local/P1-17`，没有覆盖为成功：

1. 数据库首轮 208 项中 204 通过、4 项产品测试夹具缺少导入而报错。补齐 fixture 后专项 4 项通过，随后全量 208 项通过。首轮 `postgres-integration.json` 与 XML 保留。
2. 早期浏览器脚本切换任务后没有等待服务返回的新任务编号，可能把旧任务标题当成新任务。改为等待实际提交响应并核对确切任务编号，再验证旧版本冲突。
3. 正式来源浏览器首轮在额外的重复关系查询中触发 30 秒测试工具超时。去掉重复请求，关系结果直接绑定 UI 实际响应，并设置单独的本地工具等待时限。没有把此超时冒充模型失败。
4. 后续发现产品后台轮询与按钮共用忙碌锁，可能吞掉并发点击。分离轮询与用户操作，增加延迟后台请求的浏览器检查。旧版本运行中止并标记 superseded，不作为最终验收。
5. 显式传输故障的初始断言错误地预期 `FAILED`。实际协议将未知输出标为 `PAUSED`；保留后端保守行为，修正界面说明、断言及教学，不为测试通过而把未知结果强改为已知失败。
6. 测试工具原始传输异常可能含访问请求头；改为不输出原始异常堆栈，截去调用日志并遮蔽 Bearer 字符串。此前临时访问会话随旧服务停止已失效，未上传会话或浏览器 trace。
7. 一次中止旧正式来源服务时，Windows 临时回放目录在解释器退出清理阶段报非空错误。旧记录保留；最终服务/数据库停止情况另行检查，不把该错误涂成从未发生。
8. 交付导出脚本初稿把旧记录的规范化 JSON 内容哈希误当作原始文件字节哈希，断言拒绝导出。改用旧记录原定的内容哈希函数，重新导出通过；原记录未改动。

最终接受的是 v4 两套各 19 项记录和绑定的当前代码指纹，早期 18 项记录不替代 v4 的新增故障/轮询检查。
