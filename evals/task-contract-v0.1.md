# 探索任务契约 v0.1

历史草案，已由 `evals/task-contract-v0.2.md` 替代；以下保留首次设计记录，不代表当前校验能力。

这是 P1-00 的人工字段契约草案，尚非可执行 JSON Schema，也不是 P1-01 的运行时 Task。先把业务要求写清，再根据约 10 个探索任务修订并形成机器校验。

| 字段 | 含义与本步约束 |
| --- | --- |
| schema_version、task_id | 契约版本与稳定任务编号 |
| split、event_cluster_id | 当前只能是 exploration；同一事件及其改写属于同簇 |
| status | draft，不作为正式评测输入 |
| question | 可独立理解的调查问题 |
| scope | 国家、品牌、车型、车型年、部件主题、召回编号 |
| time | 时间模式、事件时间区间、知识截止、日期过滤依据 |
| release_id | 草稿允许 null；正式运行和正式评测必须绑定完整不可变发布版本 |
| allowed_source_ids | 允许查阅的来源清单；来源内容不构成授权指令 |
| required_outputs | 每一项都应能人工判断是否满足 |
| forbidden_inferences | 有引用仍不能作出的推断 |
| missing_information_behavior | 数据缺失、条件不明和来源失败时各如何处理 |

## 时间契约

- `snapshot_analysis`：将来在指定固定快照中分析事件。当前草稿尚未绑定快照，在线查阅仅作探索。
- `historical_as_of`：只允许使用能证明在知识截止前已公开的具体内容版本。没有版本级证明，不能换成当前网页继续回答历史问题。
- 本题是召回记录查询，不筛投诉事件日期，因此 `event_interval` 为 null，必须同时解释 `date_filter_basis`。后续涉及投诉统计的题目必须明确事件区间。
- 不把车型年、接收日期、公开日期或首次观察日期当成同一个时间。

## 初始划分规则

本轮人工读过的任务、同事件改写及其受控变体均保留为探索材料，不冒充未见测试题。正式开发/测试按事件或召回簇划分，并在 P1-16 前冻结。当前尚无正式开发集和测试集。

## 初始评分草案

逐项记录“满足 / 不满足 / 无法评价”及证据位置：范围正确、证据可追溯、措辞不过强、缺信息处理正确、必需输出完整。本步不计算总分，也不设质量阈值。硬约束失败与一般质量不足分别保留。
