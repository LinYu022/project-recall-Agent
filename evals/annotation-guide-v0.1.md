# 探索证据标注与评分规范 v0.1

P1-00 产物；人工标签为助手手工核查草案，尚无第二位标注者复核，不用于宣称模型效果。

## 标注单位与证据组合

每条结论尽量只表达一个可验证事实，附车型范围、时间模式、证据位置和内容哈希。把“原记录写了什么”和“记录是否证明车辆发生了什么”分开。

`evidence_sets` 的外层表示可替代集合（或），每个内层表示必须联合出现的证据（且）。例如 `[[E1, E2], [E3]]` 表示 E1 与 E2 联合足够，或 E3 单独足够。不能把一组中的 E1 单独当作完整支持。

实际样例：EXP-002 的车型范围来自 API，通知中的风险与修复说明来自 PDF；整题参考答案要求两者联合。只提供通知的一句话不能完成该题。结论级 `claims` 与整题级 `acceptable_evidence_sets` 分开：单条成立不表示整题完整。

## 标签

- 支持度：supported / partial / unsupported_or_overstated / not_evaluable。证据存在只是必要条件；语义支持需人工阅读。
- 证据角色：support / counter / neutral。投诉自述对“确有投诉如此陈述”可构成支持，对“官方确认其说法属实”只能作为待核线索。
- 关系：scope_overlap、symptom_similar、officially_referenced、excluded_by_scope、applicability_unknown。标签只确认相应关系类型，不确认因果。
- 结果质量：证据充分、证据不足、条件待澄清、历史模式不支持等分别记载。执行完成、访问失败等运行状态另记。

## 评分草案

逐题、逐原子结论填写范围正确、来源及版本可定位、语义支持、反证处理、未知项处理、必需输出完整，各项为“满足 / 不满足 / 无法评价”。拒答/澄清与不必要拒答分别记录，不因少说话而自动高分。

错误事件计数、混用版本、缺乏因果却断言因果、把未知当适用等硬约束单列。本轮不给参考答案计算“系统正确率”；质量阈值在有开发集基线后再冻结。

## 数据集划分

当前 10 个任务全部为 exploration。已读召回、调查、投诉、比较对象及改写都记录为已暴露材料。后续先按共享事件、召回与调查关系建立簇，再分 development/test；不按文件随机切分。EXP-002 与 EXP-010 共同使用 23V162，必须放在同一泄漏隔离连通簇。

正式集建议约 60 个任务，以独立事件覆盖决定数量，不用同一事件的改写充数。对新增有效证据，在 P1-07 规定隐藏方法名的复核规则；当前不预设未知证据为错误。
